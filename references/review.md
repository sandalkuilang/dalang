# Fresh-eyes review (Step 7)

The builder sees what it meant, not what is on screen, so before Gate 4 one reviewer with no build history looks at the film. It only finds problems; the human gate still decides.

## How

1. Produce the sheets, plus an action strip per shot (`node <skill-dir>/scripts/strips.mjs --crops`, which also writes `review/strips/crop-NN.jpg`, one zoomed subject crop per shot: centre half, or `--crop X,Y,W,H` when the subject sits elsewhere; 10 %, 50 % and 90 % of each storyboard row, one row per shot on `review/strips/strip-NN.jpg`, frame → time → shot in `index.md`; the composition calls `layoutFrame(ctx, t, { format, hero: heroBox(camera, hero, W, H) })` last in its frame function (`engine/three/README.md`), so the capture also records the canvas text boxes in `layout.json` and `index.md`'s `## Layout`; from round 2 on, `--against`, step 4) so the Action test can see whether the subject changed or only the frame moved: `npx hyperframes snapshot --review --describe false` (scene sheet, a strip at every cut, a 360 px phone sheet). For a person or a generated clip, add `snapshot --at` stills sampled across the clip (about 8 per clip).
2. Spawn **one new subagent** (the Agent tool, a fresh agent — never a fork or a follow-up of the builder, which defends its own work), on the strongest model (no `model` override: the review is the quality bar). Give it only:
   - the sheet paths, the strip sheets with `review/strips/index.md`, the subject crops, and the full-res folder `review/strips/frames/`. It reads `index.md`'s `## Layout` section (the canvas text boxes in px per frame, which `hyperframes check` cannot see) before it opens any sheet: a `FLAG` line (outside the safe area, over the hero, under the minimum size, caption over a label) is a finding to confirm on its still (Clarity or Composition P1; unreadable text P0), and frames listed `Not recorded` (or `No layout recorded`) are judged from the stills. It opens a full-res still only for a frame where a sheet or crop leaves a doubt (Realism, Reality, text, a seam) and lists each under `Opened full-res:` in `QC-REVIEW.md` with the reason. A person or generated clip keeps its ~8 `--at` stills (judged in motion),
   - `SPEC.md` (LOOK, MOTION, OBJECTS with their real reference, BANNED), `storyboard.md` (each row's job, camera reason and axis — check one still at every shot's action beat against its row) and the approved style frames,
   - `visual-direction.md` §11 (the rubric), §12 (information layers), §13 (showing a quantity) and, for people, §1 "People are the hardest subject",
   - the beat list (`audio/beats.json`: name, start, words),
   - this instruction: "Find defects. For each: the beat or time, what is wrong, the rubric test it fails (its name on the line: Reality, Clarity, Action, Figure-ground…), severity P0 (must fix: Realism/Reality fail of the subject or the shot, slideshow (Action test), a hero merged into its ground (Figure-ground), wrong claim, unreadable text, broken render), P1 (should fix: craft, composition, transition, weak figure-ground separation, strobing on camera moves (Strobing), a section that fails Sound off, a fact repeated across layers (No repeat), a compared quantity shown only in text (Quantity), captions too high on 9:16 (Reels, TikTok: block top above ~70 % of the height; Shorts: block bottom above ~65 %, never the 70 % line, since its band ends at 69 %; Composition), and a Realism, Reality or Clarity defect smaller than a fail: one detail off, the narrated cause shown only in part), P2 (nice to have). Write them to QC-REVIEW.md. Do not praise; do not fix."
3. A builder subagent fixes every P0 and P1, one per round (the film's builder resumed with SendMessage, else a new one on the strongest model; never the reviewer), given the round's P0/P1 list from `QC-REVIEW.md` and the files (`look-build.md` "Parallel build"). It makes all of the round's fixes first, then one re-snapshot of only what changed (a physics set re-baked once with `bake.mjs` before it), runs `lint_scene.mjs` and `npx hyperframes check`, and returns per finding fixed / not fixed + one line, and the files touched. A fix-check subagent (`model: "sonnet"`, the mid tier) checks the new stills against the findings and returns pass/fail per item, so the stills stay out of the main context. Log the round's report and each fix in `PRODUCTION.md` (`state.mjs log`), and mark the item `FIXED` in `QC-REVIEW.md` (open P0s are what `score_run.mjs` counts).
4. After the fixes, review again only if P0s were open, or, with the user away, Realism, Reality or Clarity P1s (`qc.md` Step 7); a lean test run (`qc.md` Step 7) stops after round 1; stop after three rounds in total and list what is still open at Gate 4. Repeat rounds diff the strips: keep the last round under its own number (`mv review/strips review/strips-<n>`, n = rounds done, never an existing name), then run `node <skill-dir>/scripts/strips.mjs --against review/strips-<n> --targets <the fix list's shot numbers or beat names>` (`--threshold <pct>`, default 1, if the render is noisy). Give the new reviewer `index.md` and only the `changed` frames: `changed (targeted)` is re-reviewed against its finding; `changed (not targeted)` is a possible regression, a new finding until shown intended. `unchanged` frames keep their verdict in `QC-REVIEW.md`; a targeted shot with no changed frame (`WARN` in the output) means the fix did not show. The compare is a heuristic on a 64x36 gray copy: a very small change can pass as `unchanged`.

## Sound-off quiz (Step 7, a second fresh subagent beside the reviewer)

Clarity as a number, comparable across skill versions. The reviewer's Sound off row stays free-form.

- **`review/quiz.md`**, written at Gate 1: `| # | Beat | Question | Key |`, 5 rows: the mechanism; the key number with its comparison; the decision rule; a common misconception and its correction (phrase it so the naive answer is the wrong one); one more claim (a kind the script lacks is replaced by another claim). Each question is answerable from a headline, card or label alone and does not contain the answer's words. `Beat` is the name from `audio/beats.json`; keep beat names neutral, the answerer sees them in `index.md`. A claim changed after Gate 1: update `quiz.md` before the quiz runs.
- **Run** after `strips.mjs`, in every review round that runs: a NEW subagent (never the builder, never the fresh-eyes reviewer, which has SPEC and storyboard). Give it ONLY the strip sheet paths, `review/strips/index.md` and the questions pasted from `quiz.md` WITHOUT the Key column; never narration, script, captions, beats, SPEC or storyboard. Instruction: "Sound off, pictures only. Answer each question in one short sentence from what is on screen (headline, card, label, figure). If the frames do not show it, write 'not shown'. Do not use general knowledge; if you know the answer from elsewhere, still answer only what the frames show."
- **Score** (the main agent compares each answer with the Key; a doubt is `partly correct`): `correct` = the claim, with its number and comparison or correction where the Key has them; `partly correct` = the right idea missing the number, comparison or correction; `wrong` = a different claim, a contradiction, or `not shown`. Write `review/quiz-result.md`: `# Quiz result`, a line `Round <n>`, then `| # | Beat | Question | Answer given | Key | Verdict |`, one row per question, the verdict last. Each round overwrites it; `score_run.mjs` reads the last (correct = 1, partly correct = 0.5).
- Each `wrong` becomes a line in `QC-REVIEW.md`: `P1 | <beat> t=<time> | Clarity | quiz Q<n> wrong: <what the frames fail to carry>` (time from `index.md`), fixed like any Clarity P1 (a headline, card or label, `visual-direction.md` §12) and marked `FIXED`. `partly correct` is only recorded. Same with the user away.
- Three stills per shot can miss a card shown between them: run `strips.mjs --per-shot 5` before calling a wrong answer a real defect on a long shot.

## Asset pass (before Gate 3, and again before the Step 6 blocking pass)

Most P0s in a real run were asset defects (a machine part in the wrong place, garbled signs and page text, a product that changed shape between shots) found only after the whole film was built and rendered. Catch them while a fix is one regeneration:

1. One pair per generated or 3D OBJECTS still, beside its downloaded reference: `ffmpeg -loglevel error -y -i assets/gen/<x>.png -i review/ref-<x>.jpg -filter_complex "[0]scale=-1:960[a];[1]scale=-1:960[b];[a][b]hstack" review/pair-<x>.jpg`.
2. The same fresh subagent rules as above, on the mid tier (`model: "sonnet"`: a pair comparison against a real reference), given only the pair paths, SPEC OBJECTS and `visual-direction.md` §1 "Reality check", with: "For each pair: is the left the same kind of thing as the right — parts, where the action happens, proportions, materials; any garbled text or logo; does the same object match across pairs? P0 = Reality fail. List only defects."
3. Regenerate or re-source every P0 before building on it. The builder doesn't open full-size stills for this; the reviewer does.

## Benchmark review (Gate 3: the style frames against a reference board)

The fresh-eyes review (Step 7) finds defects; nothing else measures taste: whether the film is as good as the films the user compares it with. The style frames are the cheap moment to ask, before a look change costs a rebuild. This review is separate from the defect review and from the style-frame checker (`look-build.md` Step 5).

1. **The board.** A reference named at the Brief (Step 2): `measure/reference-board.jpg`, written by `measure_reference.sh` (two: `measure/<name>/`, both boards). No reference: the skill's golden sheet, `<skill-dir>/evals/golden/<highest version>/sheet.jpg`; when the skill copy has none, run `node <skill-dir>/scripts/golden.mjs --out review/golden` once and use `review/golden/<version>/sheet.jpg`. Boards stay local: never published, committed or shown in a post.
2. **The reviewer.** A NEW subagent (never the style-frame checker, never a builder), strongest model, given only the board path(s), the three style-frame stills, `style-frames/hook.mp4` and `SPEC.md`'s LOOK line, with: "Score the board and the style frames side by side, 1–5 each, on these rows: Detail density (parts per frame; markings legible at the macro), Material truth (each surface reads as its material), Light and shadow (contact shadows, ambient occlusion, separation), Text system (present, consistent, legible), Overlays caused by physics, Framing (subject fills the frame, text band clean, nothing clipped), Macro quality (sharpness, depth of field). Return only this table, `| Row | Reference | Style frames | Note |`, one line per row, then one line per row more than 1 point behind: what the board does that the frames do not. A row that does not apply to this look (no macro in a type-only look) gets the same score on both sides and says why in Note."
3. **Record.** The main agent writes the returned table verbatim to `review/benchmark.md` (it never opens the images) and logs `state.mjs log "5 Look | benchmark: <rows and scores> | <rows behind or ->"`.
4. **Rule.** A row more than 1 point below the board is a Gate 3 fix before the build: fix the style frames, snapshot again, a new reviewer scores again (log each round). `state.mjs approve 3` refuses while a row is behind, while `review/benchmark.md` is missing or unreadable, or when a style frame is newer than it. After two fix rounds still behind, show the user the rows at Gate 3: another fix, or another board closer to the chosen look. Same with the user away.

## Model per job

Which model each subagent job uses: `SKILL.md` "Work fast". The review, the Gate 3 benchmark and the second Realism / Reality check keep the session's (strongest) model; fix checks and asset pairs run on the mid tier.

## Autonomous mode

Same review; the reviewer's P0 list and its Realism, Reality and Clarity P1s replace the human's eye at Gate 4 (`qc.md` Step 7). Anything still open goes into the hand-off as a known bug; each open P1 with why it stays. Lean review needs the user's own word; autonomous mode alone never turns it on.
