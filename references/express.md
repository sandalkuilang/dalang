# Express mode (the default)

Express makes a 30–90 s film in **20 minutes of work at most** and **no stop after the Brief**: the agent passes every gate itself (`state.mjs approve <n> --by agent`) and hands over the finished film. It is the default answer to Brief Call 1's "Mode"; Studio (three.js 3D, reference boards, benchmark, reviewer) is the other answer. `BRIEF.md` says `mode: express`. Every rule of SKILL.md still holds unless this file says otherwise: words first, every change on a word, facts sourced, true shapes, free tools.

| Minute | Work | Who |
|---|---|---|
| 0–2 | preflight (background) and the topic question at once, folder, one Brief call | main |
| 2–5 | facts (one round, ≤ 2 research agents at once, one per independent strand, each ≤ 6 searches and ≤ 8 fetches, 4 min) → `script.md` + `narration.txt` → Gate 1 (agent) | research subagent(s), main |
| 5–12 | voice take, and at the same time the build | background job + the builder(s) |
| 12–16 | build finishes, lints | builder(s) |
| 16–20 | one render at `--quality looks` → Gate 4 (agent) → the film to the user | main |

**The main agent's turns: about 25, 30 at most** (`tokens.mjs` WARNs). Every turn re-reads the whole session, so each line below is one message of calls that do not need each other: (1) preflight ‖ topic; (2) every Brief question; (3) the folder, `BRIEF.md`, `state.mjs next --print`, the research agents; (4–8) the script, written once then edited, each lint round one chained Bash; (9) Gate 1, the voice take in the background (`> voice-take.log 2>&1`); (10) `express.mjs after-voice` (the take's warnings, padding, captions, Gates 1–2); (11) the planner (below); (12) its `scaffold.mjs` line, then every builder in one message; (13) `express.mjs assemble` (every template filled, every lint, Gate 3); (14) the one fix round, when `assemble` allows it, world owner first (below); (15) `express.mjs final` by `run_in_background` (never `nohup`/`&`: its end wakes you, a FAILED line goes to its group's builder; check, assets, render, Gate 4, metrics), `POST.md` while it runs; (16) the film to the user. `<skill-dir>/scripts/express.mjs <step> .` is one call per step: never its parts by hand. The main agent never reads `src/`, a still or a whole log.

Over budget at a step: say so with the clock time, cut scope (fewer shots, shorter film), never skip a fact check or the timing.

## Express Steps 3–4 — Script and voice

- Script as in `script-voice.md` Step 3 (beats `{text|name}`, provenance tags, `numbers_lint.mjs`, Promise and Takeaway, the narration craft, `narration_lint.mjs`, the read-through), at most 8 beats. No quiz, no arc template look-ups. The research brief: one round, one agent per independent strand (at most 2, started together), each ≤ 6 searches and ≤ 8 page fetches, original sources first; an unsourced number comes back `[unknown]`. A topic that rests on health, law, standards or measured numbers is where one thin round costs a second, sequential one: name the claim the film turns on in each brief (what the numbers or rules are, who sets them), so the budget goes to primary sources. A second round only for a core claim still `[unknown]`, started the moment the first returns.
- Approve Gate 1 yourself once `numbers_lint.mjs`, `narration_lint.mjs` and the read-through are clean (`state.mjs approve 1 --by agent`), then in one message: start the full take in the background (`tts_timestamps.mjs … --retake auto`, the voice from `BRIEF.md`; `--sample` only when the user has not heard this voice before), and nothing else: the design waits for the take's times. **The planner writes `SPEC.md` and `storyboard.md`** once `after-voice` passes: one new subagent (`SKILL.md` table: top, high; `subagent_type: "dalang-builder"`), its prompt only `Read <skill-dir>/references/express-planner.md and follow it for <film folder>.` It designs every shot (the hook, sizes, the mechanism on screen, overlay sizes, each place's props), because a film designed one row per beat by the main agent came out with a weak hook, one size for half the film and unreadable labels. You read only its report and run the `scaffold.mjs` line it ends with.
- **Room around the voice:** once the take is final, `node <skill-dir>/scripts/express.mjs after-voice .` reads its WARNING lines, pads it (1.45 s before the first word, 1.35 s after the last; every time moves with it), writes the captions and passes Gates 1–2; again after any retake.
- Gate 2 is the agent's: approve it (`state.mjs approve 2 --by agent`) when the take ends with no WARNING left; a sentence still flagged after `--retake auto` is respelled once (`--retake changed`), then named in the hand-off.

## Express Step 5 — Look in one frame

- One builder (a new one, model and effort from `SKILL.md`'s table: mid, medium) writes the whole film under 45 s; **from 45 s, 2 builders write it at once, 3 only above 75 s** (below). No asset search (one model query at most, below), no reference board, no style-frame check, no benchmark.
- **`look: isometric-world` is an editorial infographic, isometric always, `isometric-world` first** (EpicInfographics, MIT, vendored in `<skill-dir>/engine/epic/`; Studio uses the same languages in three.js, `looks.md`). `isometric-world` is the main language of every film, flat drawing made to read as 3D (2.5D) through layers and colour: three tones per face, layers moved by depth, haze and focus. `cutaway` joins it on the beats that open a thing up (the same object, its skin sliced away, numbered callouts); `blueprint` only on the beats that need engineering-grade detail (exact dimensions, tolerances, specs: an inset sheet, or a dissolve into linework of the same object). `SPEC.md` LOOK names the main language and the beats that use the other two, picked from the script without a question; the look never changes once the build starts. A request for a look outside the Brief's two (photoreal, footage, a generated image, a channel's own style) is answered in one line, and only its palette, type and overlay system are taken. The planner reads each used `languages/<name>.md` (`express-planner.md`) and writes its palette, fonts, geometry and signature devices into `SPEC.md`, the builders' law. `SPEC.md` LOOK names the language, the composition pattern and the metaphor.
  - **The frame is a place, not a page:** before drawing, say where the viewer stands ("above a model town", "beside the machine on its slab, its casing slid off"); background, texture and furniture belong to that place, with dense small detail and a story path (route, flight line, beam) that links the beats. Type and shapes on a plain ground is slop.
  - **One object carries the data:** a drawn object of the subject whose parts hold the numbers (fill level, rings, rungs, segments), labels pinned to its parts with leader lines; one hero per beat, 2–4 support forms of different kinds, never three of the same chart.
  - **Each beat's last frame is a finished infographic:** one named composition pattern (Big Object, Bleed, Overlap stack, Diagonal drive, Editorial spread, Specimen sheet), one dense zone and one empty, three sizes at least (biggest ≥ 8× body), something crossing a boundary. Truthful geometry and the hard rules of `charts.md` (area scales with value, no dual axis, ≤ 5 donut segments, text never in the data colour, numbers formatted for people, no emoji as icons).
- **`isometric-world` and `cutaway` are drawn with `engine/iso/iso.js`** (grammar after lemo-opuscar's `iso-infographic`, MIT; Canvas 2D, no three.js): the subject as a small diorama on a floating board with a cut edge, on a pale ground (`cutaway`: on paper, a `skin` slid off, ink lines and numbered callouts); charts, type and furniture are inline SVG and HTML over it. `blueprint` is inline SVG and HTML: the subject in near-white linework on blueprint blue, drawn in the same isometric view (a plan or elevation of one part only as an inset), dimension lines with real values, a title block.
  - **Isometric art, 2.5D camera:** objects are drawn with axes at 30° (`iso.js`); the camera moves layers against each other by depth (`orbit25`, `crane25`, `dollyZoom25`, `drone25`, `bokeh`, `focusRing`: `camera-motion.md`), never a tilted card.
- **`look: object-studio`** (`looks.md` "object-studio"): the builders use `engine/three` under Express rules (no reference board, style-frame check or benchmark). The engine's object-studio kit is the shared set and overlay, imported unchanged by every group, so from 45 s 2 groups (3 above 75 s) start in one message with no pilot; `SPEC.md` (sweep, palette, accent, overlay system, camera plan, objects) is their contract.
  - **Three tones per face, no outlines:** top lightest, left mid, right darkest, all from one base colour (`tri()`); solids are told apart by tone alone.
  - **Colour is a legend:** a pale ground, 5–7 hues, one ink; one hue per material or role for the whole film; the subject's hue is reserved, and to point at it everything else greys out (focus + context).
  - **Infographic furniture lives in the world:** label pins (dot → leader → rule → text) that never cover the subject, dashed cut lines, hatched section faces, a route line, a "you are here" ring, a circular inset for a close-up.
  - **Numbers are drawn, not said:** Isotype rows of identical icons that add up to the figure on screen.
  - **True shapes still:** each object built from its real parts and proportions; a machine gets its tell-tale parts, never a generic block. A cutaway shows the real inside.
  - **Everything is held, and proved:** every part rests on another part down to the ground (feet, a base, a bracket), objects touch and never sink into each other, a pipe or cable ends on a port and is held along its run. The first builder proves the world with `scripts/iso_audit.mjs` (Anatomy's geometry audit, `engine/anatomy/`) before its first snapshot and fixes the geometry until it exits 0; looking at a close-up is not proof. It also proves the labels (`PINS`: each a unique part the camera sees) and the hero's part count; every overlay anchors to `PIN.<part>`.
  - **Objects are data, not drawing code** (`engine/iso/build.js`, README there): each object is a `build()` spec written from its reference, parts of shape families at real size in metres (`box`, `cyl`, `lathe` for anything turned, `extrude` for a footprint or outline, `sweep` for pipes and roads, `gear`, `wheel`, `board`, `figure`), with `array` copies, a `skin` for the cutaway, `focus`, and numbers named as `values` the timeline drives; pins come from its `at`. A complex common object (furniture, a vehicle, a tool) may instead be one CC0 model: one `find_media.mjs --type model` query, ≤ 4000 triangles, taken into `assets/models/` and drawn by a `model` part.

## Express Step 6 — Build

**Builder brief: `scaffold.mjs` writes it** (`review/builder-<group>.md`: what to read, the cue table, the shared world, the exact checks), so each builder's prompt is one line, `Read <film>/review/builder-<group>.md and follow it.`, `subagent_type: "dalang-builder"`; never a brief of your own (a hand-written one sent builders to engine sources, wrong flags and a copy of the world per group). Its content: `SPEC.md`, its `storyboard.md` rows, its cue table (`cues.mjs`), the look's API card and templates (`isometric-world`, `cutaway`, `blueprint`: `<skill-dir>/engine/iso/templates/`; `object-studio`: `<skill-dir>/engine/three/templates/`), this section. The templates already meet the HyperFrames render contract: the `/hyperframes` skill only for what they lack. The brief holds the reads, the checks (one chained Bash per round, then at most 3 contact-sheet rounds) and the 12-line report; `assemble` runs every lint again, so this file never repeats them. **Another video's folder is off limits** (`video/<other-slug>/`: its `index.html`, `beats.js`, script, assets): the pattern comes from `engine/`, the design language files and the `/hyperframes` skill, so no earlier film's look, copy or numbers leak in.

- **Build order per beat, on the word:** the place is already there (never a blank first frame) → structure (title, axes, the object's outline, 0.4–0.8 s) → data (bars grow by `scaleY`, arcs sweep, paths draw, fills rise, icon armies populate) → the hero lands last with the biggest beat while nothing else moves → support text. Arrivals decelerate (`power3.out`); `isometric-world` and `cutaway` may overshoot a little, `blueprint` never bounces. **Truthful motion:** comparable marks share one duration and ease (stagger the delays), a count-up ends exactly on the value, an axis never moves once data sits on it.
- **Motion has a cause, led by a line:** a route or leader line draws a little ahead of what moves; a cutaway is cut line (~0.3 s) → near skin slides out along its normal (~0.35 s, ease-out) → hatched rims. Solids arrive by moving in, never by fading (a see-through block reads as a ghost); landing squash ~18 % and a small bounce; a fall eases in. Isotype icons pop with an overshoot, one per beat subdivision, the count-up number in step. Every shot keeps one continuous motion.
- Camera moves from the menu that fits the story: follow a route (cause → effect), hold wide with an inset, push through nested cutaways, a fast pull-out to the whole infographic, a locked frame while things pile up, a pan down through strata (the view never tilts). The subject ≥ 1/3 of frame height at its key moments.
- **Depth by parallax** (`engine/iso/parallax.js`): 3–4 layers at most, a far one (0.2–0.5: sky, distant skyline, paper behind), the subject (1) and a near one (1.3–1.6: a leaf, a machine edge). The world: `drawLayers(iso, cam, rest, layers)`, each layer its own pan and zoom, never a tilt; SVG/HTML furniture: one wrapper `<g>` or `<div>` per layer with `data-depth`, and `applyLayers(root, view, rest, W, H)` in the timeline's `onUpdate`. Layers move only when the camera does; a near layer crossing the lens is the occlusion wipe between beats.
- **Shot like a film** (`engine/iso/cinema.js`, README there): pick 4–6 techniques in `SPEC.md` CAMERA, each with its story job (`camera-motion.md` §11–12), never all. The camera moves between keyed poses (`camAt`: eased, zoom in log), its life a slow `orbit25` in one direction for the whole film (never a handheld shake); `drawLayers` options give depth of field (`focus` racked on the beat word from subject to detail) and `haze` (far layers paler); `ramp` slows story time into the impact; `whip` + `motionBlur` (16–24 samples) cut between places; `makeFinish(...).apply` once per frame, last: a grade per section (warm or cool, contrast), bloom on what glows, a light sweep on a reveal, vignette, grain 0.04–0.06, and scope bars (2.39) eased in for the establishing shot or the climax only.
- Text: the language's fonts and size scale, scaled to the frame (its scale is for a 1080 px canvas; set `FONT` in `assets/iso.js` for canvas text), big numbers with half-size units; captions from `WORDS` in the language's caption style at the bottom (keep that zone clear).
- Pitfalls: give every face an outward hint (else it is culled), draw a composite as one ordered item, leave clearance between a wheel and the floor, skip small detail when zoomed in close.
- Audio: the padded voice (`audio/voice.wav`); a music bed always, from the bundled public-domain / CC0 tracks (`scaffold.mjs --music calm|bright|tense`, picked from the energy: calm by default, bright for upbeat, tense for a problem that builds; it writes the licence row and puts the bed at 0.14 under the voice with fades), no search and no listening; SFX only from the bundled `/media-use` library (`find_media.mjs --type sfx --bundled`). No web search for media.
- Log the build: `state.mjs log "6 Build | index.html | <problems or ->"`.
- **Token budget: a film is 10M tokens, main agent and subagents together** (`tokens.mjs` WARNs above it; quality first: a 4M film lost its design): the main agent ≤ 2M (≤ 30 turns, in a lean folder, `brief.md` "Lean workspace"), the planner ≤ 3M, each builder ≤ 1.5M (about 25 turns, 30 at most, its context under 150K; a fix round 10 turns), research ≤ 0.3M, checkers ≤ 0.1M. A builder over 150K has read something its brief did not name. A subagent's cost is its turns × its context: every turn pays the base again, and what entered early is paid on every later turn. Measured on test films: printed engine and example sources a third, turns × base a third, files written whole a fifth, screenshots 3 %; fix rounds cost more than the builds. So: `subagent_type: "dalang-builder"` (its rules: read only what the brief names, write once then Edit, independent calls in one message, one chained check per round cut to errors, ≤ 2 contact-sheet rounds); the brief names the files, the API card (`engine/iso/templates/iso-API.md` or `engine/three/templates/object-studio-API.md`), `SPEC.md`, the template, the checks. Never another film's files. At the budget it reports and stops: a new builder takes the rest.
- **One fix round, one fixer per group:** none when `assemble` prints SKIP (over 8M). A fix that changes `assets/world.js` goes to its owner first, alone; the other groups' fixers start after it reports (a world moving under a fixer wastes its round). Each gets all its findings at once (time or file, the exact change), reads only the lines it changes (`grep -n`, ≤ 30 lines) and stops at 10 turns, effort medium (no escalation: a fix round that took 20 turns at high cost as much as a build). An error every group shares (a font, a helper) is one fix for all groups, never one per group. A defect that comes back after its fix gets a different route (another form, a simpler part, a changed shot), never the same fix again. A fixer changes only its own group's files; `express.mjs final` lists every file changed since `assemble`, and the main agent checks each against the round's assignments. A finding the round did not fix ships named in the hand-off. Builders and fixers report each check as PASS (with its command's result line), FAIL or UNVERIFIED; a missing result is never a PASS.

### Parallel build (45 s or more)

Build time is the longest serial step, so a longer film is written by 2 builders in one message (3 above 75 s). Under 45 s one builder is faster than the hand-offs, and each extra builder reads the brief, SPEC, card and world again.

- **Groups:** cut the beats into 2 runs (3 above 75 s) of neighbouring beats with about equal runtime. `SPEC.md` is the contract all of them share (language, palette hex, fonts, easing, caption style, the camera techniques); the planner writes it before any builder starts, so there is no pilot.
- **Each group is a sub-composition** (`look-build.md` "Parallel build" item 2: `src/compositions/<group>.tpl.html` → `compositions/<group>.html`, local times, group-prefixed ids). A builder touches only its own template, never `src/index.tpl.html`, the audio or another group. Brief each with the other groups' beat names, so a seam is planned: one group ends on its held last frame, the next opens in the same place and ground colour. **Seams by construction:** `SPEC.md` CAMERA gives each group's first and last pose (`{ x, y, z, k }`), a group's first pose is the previous one's last, and the world is one file, `assets/world.js` (isometric looks; written by `scaffold.mjs`, filled once by the first group's builder from `SPEC.md` OBJECTS, imported by every group, never copied: three copies cost three times the output and drift apart); a seam that still jumps is fixed by editing those numbers, never by a builder reading every group.
- **`scaffold.mjs` writes the frame before any builder starts** (`node <skill-dir>/scripts/scaffold.mjs . --look <look> --groups <name>:<first beat>,… --illustration "<label>"`): the engine in `assets/`, the host `src/index.tpl.html` with every group on the narration's times (the first from 0, the last to the end), and each group's template from the look's, beat names filled. Builders only Edit their own group's data. When all report, the main agent runs `express.mjs assemble .` (every template filled, every lint, Gate 3); a failure goes back to that group's builder only, replaced by a new one a notch up (`SKILL.md` "Escalate").
- The seams are measured, never looked at: `assemble` runs `seam_gate.mjs`, which reads each group's camera on both sides of every cut. A jump (a group opening away from the previous one's last frame) or a move that turns back or flips its zoom at the cut is FAILED, for the two groups' builders, with the SPEC CAMERA pose to change; a move that stops dead or starts from rest at the cut is a NOTE. No seam subagent, no snapshot of the seams.

## Express Step 7 — Render → GATE 4

- One call, in the background: `node <skill-dir>/scripts/express.mjs final .` (render at the brief's fps, `--quality looks`, `hyperframes check`, `check_assets.mjs`, Gate 4, the metrics table). No 10 fps draft, no strips, no reviewer, no quiz, no assembly builder.
- Approve Gate 4 yourself (`state.mjs approve 4 --by agent`) once `check` passes, and send the film. A change the user asks for afterwards goes to a new builder with the list; render again.
- `--quality high` only when the user asks for it. Hand-off: `POST.md`, then `node <skill-dir>/scripts/state.mjs metrics` and its table pasted at the end of the message to the user: start, end and total time, the output folder, minutes per step, each subagent's job, model, effort and tokens.
