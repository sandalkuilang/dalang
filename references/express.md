# Express mode (the default)

Express makes a 30–90 s film in **20 minutes of work at most** with **no stop after the Brief**: the agent approves every gate itself (`state.mjs approve <n> --by agent`) and hands over the finished film. `BRIEF.md` says `mode: express`; Studio (`looks.md`) is the other answer to Brief Call 1's "Mode". Every SKILL.md rule holds unless this file says otherwise.

| Minute | Work | Who |
|---|---|---|
| 0–2 | preflight (background) ‖ topic question, folder, one Brief call | main |
| 2–5 | facts (one round, below) → `script.md` + `narration.txt` → Gate 1 | research subagent(s), main |
| 5–12 | voice take in the background; planner, then builders | background job, subagents |
| 12–16 | build finishes, lints | builder(s) |
| 16–20 | one render at `--quality looks` → Gate 4 → film to the user | main |

**The main agent's turns: about 25, 30 at most** (`tokens.mjs` WARNs). Each item is one message of independent calls: (1) preflight ‖ topic; (2) every Brief question; (3) folder, `BRIEF.md`, `state.mjs next --print`, research agents; (4–8) the script, written once then edited, each round one `state.mjs approve 1 . --by agent` (it runs both lints and refuses with every problem); (9) the take in the background (`> voice-take.log 2>&1`; a clean take runs `after-voice` itself, which prints Steps 5–6's reading); (10) the planner, once the take's log ends `Result: OK` (a take with a WARNING: respell, `--retake changed`, again); (11) every builder in one message, from the planner's `next:` line; (12) `express.mjs assemble` ‖ the anatomy check when `research/anatomy.md` exists (`dalang-checker`, mid · low): `Film <film>. Read research/anatomy.md, open each refs/anatomy-* picture and each style-frames/*/contact-sheet*.jpg once. Write review/anatomy-check.md: one row per part of the table (present, missing, misplaced, wrong proportion; the frame), then any part drawn that the table lacks. A part missing, invented or misplaced is P0. Reply ≤ 5 lines.`; (13) the one fix round, if `assemble` allows it; (14) `express.mjs final` by `run_in_background` (never `nohup`/`&`), `POST.md` while it runs; (15) the film to the user. Run `<skill-dir>/scripts/express.mjs <step> .` as one call per step, never its parts by hand. The main agent never reads `src/`, a still or a whole log.

Over budget at a step: say so with the clock time and cut scope (fewer shots, shorter film); never skip a fact check or the timing.

## Express Steps 3–4 — Script and voice

You write no script and run no take: every turn of yours re-reads the whole session, a subagent's turn a fraction of it. The jobs know only the files, so first put into `BRIEF.md` (`notes:`) anything the user said in chat or memory holds for this channel (voice, style, words to avoid) that it lacks. Four jobs, each a new subagent whose prompt is the line given (`<film>` the folder, nothing pasted), each started the moment the one before replies:

1. **Facts** (`dalang-research`): one job, at most 2 strands, ≤ 6 searches and ≤ 8 fetches in all, original sources first; an unsourced number comes back `[unknown]`. For health, law, standards or measured numbers, the prompt names the claim the film turns on and who sets it. A second job only for a core claim still `[unknown]`.
   **Anatomy strand**, in the same job, whenever the film explains one object, made or natural (a device, a machine, an appliance, a building system, an organ, a plant, a volcano), so every SPEC hero has one: ≤ 3 more searches and ≤ 4 more fetches. Sources in this order: `BRIEF.md` `docs:` (read first, no search), then the maker's owner's or service manual and datasheet for `BRIEF.md` `model:` (or the most common model when none), a patent's figures, a published teardown or exploded view. Save 2–3 pictures to `refs/anatomy-<n>.<ext>` (the outside from two sides, the inside); never published. Fewer than 2 saved (no outside or no inside): write an `Ask:` line in `research/anatomy.md` holding this prompt with `<thing>` filled from `Thing:`. The main agent passes it to the user once, in its next message, word for word (a subagent cannot talk to the user): run it in your own image tool and save the two images as `refs/anatomy-gen-1.png` (outside) and `refs/anatomy-gen-2.png` (inside), or say skip. Nothing waits for the answer: the script and the take go on, and the planner uses the pictures only if they are there when it starts. Never call an image service yourself:
   `A 3D isometric 2.5D infographic visualization of <thing>, delivered as two images in a before-and-after comparison. Image 1 shows the complete, intact exterior. Image 2 shows a cutaway section of the interior, revealing the internal components it really has (electronic, mechanical or structural), precise and true to the real-world object. Clean technical-diagram style, soft lighting, modern UI elements, plain white background.`
   They are a reference for composition and the cutaway's arrangement only, made by the user's own tool outside the film: never in the film, never published, never a part's source (an image model invents insides; the sourced table wins). The user skips: go on without them, `Refs:` says so. Write `research/anatomy.md`:
   - `Thing:` what it is and the model the sources describe (or "generic: <why>").
   - `Size:` length × width × height with its tag (`[src: …]`, `[assume]`).
   - A parts table `| # | Part | Count | Inside or touches | Material | Size | Moves, and what moves it | Tag |`, every part a source shows down to fasteners, seals and housing halves (an exploded view numbers them), 15 rows or more, tagged like script numbers; structure no source shows is a "generic" row, drawn plain, never invented.
   - `Refs:` each saved picture, what it shows, its source (`generated by the user's image tool: reference only` for `anatomy-gen-*`), or `none: <why>`.
   A thing no source opens up (no manual, patent or teardown found) gets `Thing: generic: no inside found` and the parts the outside shows, plus generic structure rows; the narration then never claims its inside.
2. **Writer** (`dalang-builder`, top · high): `Film <film>, Express: at most 8 beats, no quiz. Run node <skill-dir>/scripts/state.mjs next <film> --step 3 --sub and write Step 3 (script.md, narration.txt) from BRIEF.md, research/ and the pictures in refs/. Lints clean; never approve, never spawn. Report review/reports/script.md (Promise, Takeaway, the number → tag → source table), reply ≤ 10 lines.`
3. **Read-through** (`dalang-checker`): `Read only <film>/narration.txt. Write review/read-through.md: the topic in one sentence, what a viewer learns, the parts in order, each term you could not explain, each sentence you could not follow and why. Reply ≤ 5 lines.` Topic and learning match Promise and Takeaway: `state.mjs approve 1 --by agent` and the voice job in one message; else a new writer gets that path.
4. **Voice job** (`dalang-builder`, top · medium: a respell is a language judgement): `Film <film>. Run node <skill-dir>/scripts/state.mjs next <film> --step 4 --sub and make the take with BRIEF.md's voice (--sample only for a voice the user has not heard), --retake auto: every tts_timestamps.mjs call in the foreground (timeout 600000; one that times out is run again, it resumes); a sentence still flagged is respelled once in narration.txt, --retake changed. Never approve. Report review/reports/voice.md (the Model line and licence, words/s, any sentence still flagged), reply ≤ 8 lines.`

**Room around the voice:** a take or retake that printed no WARNING runs `express.mjs after-voice` itself (`BRIEF.md` `mode: express`): it pads the take (1.45 s before the first word, 1.35 s after the last), writes the captions and passes Gates 1–2. A sentence the voice job reports still flagged is named in the hand-off, and you run `node <skill-dir>/scripts/express.mjs after-voice .` in the foreground. Then `state.mjs next --print` (Steps 5 and 6) beside the planner.
- **The planner writes `SPEC.md` and `storyboard.md`** once `after-voice` passes: one new subagent (top, high; `subagent_type: "dalang-builder"`), prompt only `Read <skill-dir>/references/express-planner.md and follow it for <film folder>.` It ends by running `express.mjs scaffold .` (storyboard lint, then `scaffold.mjs` from `SPEC.md`'s `SCAFFOLD:` line); you read only its report and start the builders from its `next:` line.

## Express Step 5 — Look in one frame

- **`look: isometric-world`: isometric always, `isometric-world` first** (EpicInfographics, MIT, in `<skill-dir>/engine/epic/`); `cutaway` and `blueprint` on the beats `looks.md` gives them, picked from the script without a question; the look never changes once the build starts. A request for a look outside the Brief's two (photoreal, footage, a generated image, a channel's own style) is answered in one line; only its palette, type and overlay system are taken. **`look: object-studio`** (`looks.md` "object-studio"): `engine/three` under Express rules; its kit is the shared set and overlay, so from 45 s 2 groups (3 above 75 s) start in one message with no pilot.
- **The user's own thing, traced** (they brought photos), in the same message as the planner: `node <skill-dir>/scripts/trace.mjs <photo> --out assets/plates/<name> [--crop x,y,w,h] --part <layer>=cx,cy,rx,ry,deg,front|back,<pick> --select <layer>=<pick>`, once per photo (vtracer; install only on the user's yes; exit 2 is a WARN: no vtracer, or retake on a plain wall). Each moving part is an ellipse in photo fractions plus the colour of its own pixels (pale fan blades `hsv:15-65/0.03-0.4/0.42-1`, never the coil between); each tinted material a pick (copper `hue:12-38,35`), read off the photo. The world shows it as a `plate` part (`iso-API.md`); everything around it comes from kits. Trace only a supporting object or the user's own thing (logo, product, drawing, machine), never a precision-lane hero (`hero-asset.md`).
- **A hero already modelled is reused:** when `<videos folder>/library/hero/<name>/` holds the subject (`hero-asset.md`),
  object-studio places its GLB (built once with its `.py`) and the isometric look draws to its proportions; Express never
  models a new hero (that is Studio).
- No asset search beyond the anatomy strand's pictures (one model query at most), no reference board, no style-frame check, no benchmark. The planner turns the rules below into `SPEC.md`, the builders' law.

### Look rules (the planner writes them into `SPEC.md`)

- **The frame is a place, not a page:** say where the viewer stands ("above a model town", "beside the machine, its casing slid off"); background, texture and furniture belong there, with dense small detail and a story path (route, beam) linking the beats.
- **One object carries the data:** its parts hold the numbers (fill level, rings, segments), labels pinned to parts with leader lines; one hero per beat, 2–4 support forms of different kinds.
- **object-studio shots are planned to be measured:** plan every shot with the hero at least a third of the frame height or width and not cut by an edge (a close-up fills the frame), no headline, card, tag, pill or caption over the hero, and a hero at least 12 ΔE* (colour difference, not lightness alone) from the ground around it (a pale hero gets a darker material or a backdrop); assemble measures all of it.
- **Each beat's last frame is a finished infographic:** one named pattern (`engine/epic/composition.md`), one dense zone and one empty, at least three sizes (biggest ≥ 8× body), something crossing a boundary; the hard rules of `charts.md` (area scales with value, no dual axis, ≤ 5 donut segments, text never in the data colour, no emoji icons).
- **Drawing:** `isometric-world` and `cutaway` with `engine/iso/iso.js` (Canvas 2D; after lemo-opuscar's `iso-infographic`, MIT): the subject as a small world on a floating slab with a cut edge on a pale ground (`cutaway`: on paper, a `skin` slid off, ink lines, numbered callouts); charts, type and furniture in inline SVG/HTML over it. `blueprint`: near-white linework on blueprint blue in the same isometric view (a plan or elevation only as an inset), dimension lines with real values, a title block. Axes at 30°; three tones per face from one base (`tri()`: top lightest, left mid, right darkest); every solid inked (silhouette + crease lines, `iso.ink` by default; `iso.ink = null` for a flat look).
- **Colour is a legend:** pale ground, 5–7 hues, one ink; one hue per material or role for the film; the subject's hue reserved, everything else greys to point at it.
- **Furniture lives in the world:** label pins (dot → leader → rule → text) never over the subject, dashed cut lines, hatched sections, a route line, a "you are here" ring, a circular inset for a close-up. **Numbers are drawn:** Isotype rows that add up to the figure.
- **Objects are data** (`engine/iso/build.js`): each a `build()` spec from its reference, shape families at real size in metres (`box`, `cyl`, `lathe`, `extrude`, `sweep`, `gear`, `wheel`, `board`, `figure`), `array` copies, a `skin`, `focus`, numbers as `values`; pins from `at`. Real parts and proportions, never a generic block; a cutaway shows the real inside. A complex common object may be one CC0 model (one `find_media.mjs --type model` query, ≤ 4000 triangles, into `assets/models/`, a `model` part).
- **Everything is held, and proved:** every part rests on another down to the ground, nothing sinks, a pipe ends on a port. The first builder runs `scripts/iso_audit.mjs` (`engine/anatomy/`) before its first snapshot until it exits 0, and proves `PINS` (each a unique visible part) and the hero's part count; every overlay anchors to `PIN.<part>`.
- **Build order per beat, on the word:** the place is already there → structure (title, axes, outline, 0.4–0.8 s) → data (bars by `scaleY`, arcs sweep, paths draw, fills rise, icons populate) → the hero lands last while nothing else moves → support text. Arrivals `power3.out`; `isometric-world` and `cutaway` may overshoot a little, `blueprint` never. Comparable marks share one duration and ease; a count-up ends exactly on its value; an axis never moves once data sits on it.
- **Motion has a cause, led by a line:** a route or leader draws a little ahead of what moves; a cutaway is cut line (~0.3 s) → near skin slides out along its normal (~0.35 s) → hatched rims. Solids move in, never fade in; landings squash and bounce (`camera-motion.md` §5.2). Isotype icons pop one per beat subdivision with the count-up. One continuous motion per shot.
- **Camera:** follow a route, hold wide with an inset, push through nested cutaways, a fast pull-out, a locked frame while things pile up, a pan down through strata (never a tilt). The subject ≥ 1/3 of frame height at its key moments. Pick 4–6 techniques (the planner's card in `express-planner.md`) in `SPEC.md` CAMERA, each with its story job; `camAt` keys (eased, zoom in log), life a slow one-way `orbit25` (`camera-motion.md` §2 "No handheld"); `drawLayers` `focus` racked on the beat word, `haze`; `ramp` into the impact; `whip` + `motionBlur` (16–24 samples) between places; `makeFinish(...).apply` last each frame (grade per section, bloom on what glows, a light sweep on a reveal, vignette, grain 0.04–0.06, 2.39 bars only on the establishing shot or climax).
- **Depth by parallax** (`engine/iso/parallax.js`; the one home of the ratios): 3–4 layers, far 0.2–0.5, subject 1, near 1.3–1.6. The world: `drawLayers(iso, cam, rest, layers)`; SVG/HTML: one wrapper per layer with `data-depth`, `applyLayers(root, view, rest, W, H)` in `onUpdate`. Layers move only with the camera; a near layer crossing the lens is the occlusion wipe.
- **Text:** the one typeface, weight by role (Bold title, Semibold heading, Medium sub-heading, Regular body; `FONT` in `assets/iso.js` for canvas text), the language's scale for a 1080 px canvas, big numbers with half-size units; captions from `WORDS` at the bottom (zone kept clear).
- **Pitfalls:** every face needs an outward hint (else culled); a composite is one ordered item; clearance between a wheel and the floor; skip small detail when close.

## Express Step 6 — Build

- **`scaffold.mjs` writes each builder's brief** (`review/builder-<group>.md`: reads, cue table, shared world, exact checks); each prompt is one line, `Read <film>/review/builder-<group>.md and follow it.`, `subagent_type: "dalang-builder"`; never a brief of your own. Builders read the look's API card (`engine/iso/templates/iso-API.md` or `engine/three/templates/object-studio-API.md`) and template, never `/hyperframes` (the template meets the render contract), never another video's folder.
- **Audio:** the padded `audio/voice.wav`; a music bed always from the bundled tracks (`scaffold.mjs --music calm|bright|tense` from the energy, calm by default; licence row written, bed at 0.14 with fades); SFX only from the bundled `/media-use` library (`find_media.mjs --type sfx --bundled`). No media search.
- Log: `state.mjs log "6 Build | index.html | <problems or ->"`.
- **Token budget: 10M tokens a film, all agents** (`tokens.mjs` WARNs): main ≤ 2M (≤ 30 turns, lean folder, `brief.md` "Lean workspace"), planner ≤ 3M, each builder ≤ 1.5M (about 25 turns, 30 at most, context under 150K; a fix round 10 turns), research ≤ 0.3M, checkers ≤ 0.1M. A builder over 150K read something its brief did not name. At the budget a builder reports and stops; a new one takes the rest.
- **Fix rounds:** one, one fixer per group; none when `assemble` prints SKIP (over 8M). A fix to `assets/world.js` goes to its owner first, alone; the others start after it reports. Each fixer gets all its findings at once (time or file, exact change; `review/anatomy-check.md`'s P0 rows go to the world's owner), and object-studio: `assemble`'s measured-frames lines (the hero under a third of the frame or cut by an edge, a caption over the hero, the hero under 12 ΔE* against its ground) go to their group's fixer, like any other assemble failure; `final` measures again and prints what is still open as OPEN lines for the hand-off, not a stop; there is no polish round after `final`, reads only the lines it changes (`grep -n`, ≤ 30 lines), effort medium, stops at 10 turns. An error all groups share is one fix. A defect back after its fix gets a different route (another form, a simpler part, a changed shot). A fixer changes only its own group's files; `express.mjs final` lists every file changed since `assemble` and the main agent checks each against the assignments. Every fixer reruns `film_gate.mjs . --group <group>`; a seam FAILED goes to the later group (its first CAMERA key back to `{ t: 0, ...OPEN }`). Checks are reported PASS (with the result line), FAIL or UNVERIFIED. An unfixed finding ships named in the hand-off.

### Parallel build (45 s or more)

2 builders in one message (3 above 75 s); under 45 s one builder.

- **Groups:** neighbouring beats, about equal runtime. `SPEC.md` is the shared contract, written before any builder starts: no pilot.
- **Each group is a sub-composition** (`look-build.md` "Parallel build" item 2: `src/compositions/<group>.tpl.html` → `compositions/<group>.html`, local times, group-prefixed ids). A builder touches only its own template. **Seams by construction:** `SPEC.md` CAMERA gives each group's first and last pose (`{ x, y, z, k }`), a group's first = the previous one's last; one world file, `assets/world.js` (written by `scaffold.mjs`, filled once by the first group's builder from `SPEC.md` OBJECTS, imported by every group, never copied). A seam that jumps is fixed in those numbers.
- **`scaffold.mjs` first**, run by the planner through `express.mjs scaffold .` (`SPEC.md` `SCAFFOLD: --look <look> --groups <name>:<first beat>,… --music <bed>`): engine in `assets/`, host `src/index.tpl.html` with every group on the narration's times, each group's template. When all builders report, `express.mjs assemble .` (templates filled, every lint, Gate 3); a failure goes to that group only, a new builder a notch up (`SKILL.md` "Escalate").
- **Measured, never looked at:** `assemble` runs `film_gate.mjs` over each group's camera, world values and overlays. FAILED (to that group's builder): a jump at a cut, a move that turns back or a zoom that flips at a cut, a part that floats, sinks or is passed through while the world moves, an overlay settled under max(0.8 s, 0.3 s a word), a close-up past the drawing's detail (one part over half the frame, or three over three quarters). NOTE: a dead stop or start from rest at a cut, 3 s with nothing moving. Builders run it on their own group first (`--group`).

## Express Step 7 — Render → GATE 4

- One background call: `node <skill-dir>/scripts/express.mjs final .` (object-studio: the frames measured again, open lines for the hand-off; render at the brief's fps, `--quality looks`, `hyperframes check`, `check_assets.mjs`, the hook's last frame as `poster.jpg` over frame 0, Gate 4, metrics). A FAILED line goes to its group's builder. No draft, strips, reviewer or quiz.
- Approve Gate 4 once `check` passes and send the film. A later change the user asks for goes to a new builder with the list; render again.
- `--quality high` only when the user asks. Hand-off: `POST.md`, then the metrics table `express.mjs final` printed, pasted at the end of the message.
