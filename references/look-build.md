# Steps 5–6: look, storyboard, style frames, build

## Step 5 — Look, storyboard, style frames → GATE 3

A **planner subagent** (strongest model, a new one) does this reading and writing, never the main agent. Brief it with `BRIEF.md`, `script.md`, `audio/beats.json` and the `sed` lines from `state.mjs next`; it writes `SPEC.md` and `storyboard.md` and returns ≤ 15 lines (files, open questions). The main agent reads only those two files, then runs the lints. It writes:

- `SPEC.md` (template: `/hyperframes` `references/spec.md`): LOOK (the language, `looks.md`; the energy in numbers: palette hex, faces and weights, zoom levels, grain, average shot length), MOTION and ANCHORS (`camera-motion.md` §7), OBJECTS (each physical thing, its source: drawn, the Blender hero asset, built, or a CC0 model, and the real reference it is checked against; one modelled in code adds a parts line, 3–6 things its reference shows, e.g. `parts: 2 chainrings · chain on the right · valve at the rim`), BANNED. Never skip it.
- `storyboard.md`: the arc, a colour-script line and the axis per section (`camera-motion.md` §3), then the shot table, times from `beats.json`:

| # | Time | Beat | Job · emotion | Size · angle · lens | What we see (focal point; fg / mid / bg job) | Camera (+ what changed) | Subject action (+ source) | Transition out (+ what fires it) | SFX (J/L) | Overlay (headline · cards · labels) |
|---|---|---|---|---|---|---|---|---|---|---|
| 1 | 0.00–1.60 | `hook` | A · establish | macro · zoom k 4 | the hero mid-action (focal); its context blurred mid | push 1.00→1.04 | the hero's key action on the hook word (3D) | speed ramp into the cut on the next beat word | the action's sound, J −0.3 s | kicker + headline: the hook's claim; card A: its value counting |

Check, every row:
- names its emotion; size, move, colour and angle (an isometric row writes the angle as the subject's view: `front`, a side, `back`, the camera never tilts; a hard cut turns it 60° or more, `camera-motion.md` §2) and, for `object-studio` only, lens and light (an isometric row writes size as a zoom and light as the grade) follow `camera-motion.md` §10 or the SPEC rulebook; a choice without a motivation is cut, a rule break is logged;
- "Subject action" names a real action and its source (three.js, a drawn layer, a `/hyperframes-registry` block via `catalog --query` in English); camera-only rows ≤ 15 % of the runtime; every "why" beat has its mechanism shot (`visual-direction.md` §8 "Motion is the explanation"); each shot where the subject acts has its motion built, each person is stylized or faceless (`visual-direction.md` §1 "People");
- the Job column marks A or B roll, pattern per `camera-motion.md` §8; every perceptible move is a real camera move, never CSS on a still; the Camera column names its technique from the SPEC palette (`camera-motion.md` §9); one wow shot on the impact;
- every physical OBJECTS item has a true source; a generic vector stand-in is a blocker;
- the Overlay column (written now, never per scene in Step 6) names which layer carries which fact (`visual-direction.md` §12): a headline per claim beat, ≤ 3 cards, sides and hues fixed, no fact in two layers, the headlines alone tell the argument;
- the hero meets `visual-direction.md` §7's size; one hero move per shot; few hard cuts at Calm; a reference's numbers are used (Step 2);
- shot grammar: arc named, Crack and Impact present, each scene keeps its axis, sizes tighten toward the key beat, macro inserts have their own asset, a pause before the biggest cut, no two bursts touching, the final image is the payoff frame.

Then `node <skill-dir>/scripts/storyboard_lint.mjs`: exit 1 names the row (empty Subject action or Camera, 3+ rows alike, too much text, shots too long, `visual-direction.md` §3); fix and log. `state.mjs` refuses Gate 3 on a benchmark row > 1 behind, and Step 6 before Gate 3. With a Blender hero the planner also writes `review/hero-shots.json` (one row per shot that shows it, `hero-asset.md` §3) and runs `node <skill-dir>/scripts/hero_shots.mjs .` until clean.

Then get the hero assets: every OBJECTS item in one call (`find_media.mjs --type image --query "a|b|c" --out review/<dir>`: CC0 / CC BY / PD stills from Commons and Openverse, 1–2 English words per query), never a shell loop. The hero: `hero-asset.md` (code-first by default; its §1 beside the planner; with the user's pictures and `fidelity: exact`, their `refs` rows and IoU per view; modelling only once `hero-shots.json` is clean, measured as §3 says). Any other made object with internal anatomy: `--type model` first (`visual-direction.md` §1.1); `--take` prints the `kit.model(path, { palette, kinds, real })` line. Queue every still in one background chain, style-frame ones first. **Every file that lands in `assets/`** gets its `ASSETS.json` row at once (file, source URL or "user", licence, author; format in `scripts/check_assets.mjs`; `find_media.mjs --take` writes it). A derived file overwrites the taken path or gets its own row. Engine files are never rows (`.engine.json`).

**Style frames** (the look test): a small composition in `style-frames/src/` with the real assets and rig: the hook scene at its real timing from 0 s with the narration `<audio>`, the hardest action shot (ideally the wow shot), one B-roll with its real move, and the payoff, as ~3 s clips. Load only the `/hyperframes` contract and `references/format.md` (plus `types/vertical.md` for 9:16), use the scaffold in §6. They start only once their OBJECTS stills have landed: the media screening writes `review/refs-board-<frame>.jpg`, one per frame, and each modelled object's parts line (`review.md` "Asset pass" 3; text only); a builder writes `style-frames/src/` (never the main agent; its brief names the boards) and opens each board once before its first write; fix rounds reuse them, never re-fetch. Then one background call, `node <skill-dir>/scripts/studio.mjs frames . --at <t1>,<t2>,<t3>` (the mid points): the stills on one sheet in `review/style-frames/`, the **moving sample** `style-frames/sample.mp4` and `style-frames/hook.mp4`. One subagent checks the stills against `SPEC.md` (parts lines) and the OBJECTS references and writes `review/style-frame-check.md`, a second scores them against the reference: its board, or the look's rules when there is no reference video (`review.md` "Benchmark review"); text only. Step 6 seeds its first template from these scenes. Build nothing else before Gate 3. Run the asset pass (`review.md`) on the stills, then `state.mjs approve 3 --by agent`.

## Step 6 — Build (hand off to /hyperframes)

1. Load `/hyperframes` and only the type guides this video needs (`types/explainer.md`, `types/character.md`, `types/data.md`, `types/3d.md`, `types/vertical.md` for 9:16). Answer its questions from `BRIEF.md`, `script.md`, `storyboard.md`, `SPEC.md` without asking the user, but **do not skip its design steps**: it follows the LOOK, OBJECTS and BANNED lines.
2. Style frames are the reference per scene; builders write the set and its shot data, not per-shot code: "Parallel build". Render a 3D set with `isoStudio()` (`object-studio`: `studio()`), never a hand rig.
3. Search the catalog before building an effect, queries **in English**: `npx hyperframes catalog --query "<what the beat needs>"`, then `npx hyperframes add <name>`.
4. Load `audio/beats.js`; **every** animation time references `BEATS.<name>.start`, or `WORDS[i].start` for a change on a non-beat word. Never hard-code seconds or numbers (`script-voice.md` "Numbers model"). HTML attributes can't read JS: write `{{beat_name - 0.05}}` in the template (`src/index.tpl.html`; a group's own: "Parallel build") and run `node <skill-dir>/scripts/fill_times.mjs <template> <output>` after every template edit and new take. Captions on a three.js canvas: `node <skill-dir>/scripts/captions.mjs audio/narration.txt audio/words.json` after every take, load `audio/captions.js` (`CAPTIONS`), draw with `type.js` (`drawCaption(ctx, t, CAPTIONS, { format, accent })`, `pinLabel` for part labels, `layoutFrame` last, `craft-rules.md` §5), then `repeats(CAPTIONS, LABELS)` prints nothing. Headlines and cards come from the Overlay column (`visual-direction.md` §12), in the text band above the caption, timed from `BEATS`/`WORDS`; add their texts (with `from`/`to`) to `repeats()`.
   Scaffold facts (each a lint round when missed): include GSAP yourself (`<script src="https://cdn.jsdelivr.net/npm/gsap@3.14.2/dist/gsap.min.js"></script>`, before your timeline script); time a `<video>` **or** its wrapper, never both; `media-treatment` adds `data-hf-id` to every tag, so edit the template with Edit, not `sed`; never SVG inside a `<template>` (renders empty), never `mix-blend-mode` on an SVG `<rect>` (paints opaque); set every face with `font-family`, never the `font:` shorthand (the subsetter skips it); the same hero across a cut is a match cut, never a crossfade; prefix every `id` with its scene (`hk-`, `calc-`); a whip pan moves both plates in the same window, each overscanned.
5. **Blocking pass (animatic):** the asset pass (`review.md`) on the stills made since Gate 3; then every scene at final timing with rough motion. Render once at `--fps 10 --quality draft --quiet`, watch it against the narration (rhythm, shot variety, colour script) and run `stillness.mjs` on it: too little motion is a structure problem (`visual-direction.md` §3 "Minimum motion"), cheap to fix here.
6. **Polish pass:** craft (`visual-direction.md` §4; `camera-motion.md` §5, §6), finish (§9: contact shadows, one light direction, grade and grain through `media-treatment`), depth and parallax. Captions at the target position of `craft-rules.md` §5, checked on the phone sheet.
7. Audio: normalise the padded voice (`loudness.mjs audio/voice.wav --fix <project>/assets/narration.m4a`, near −14 LUFS); music ducked under it (`/media-use` `references/mixing.md`); physical SFX on their computed contact times (`camera-motion.md` §5.3), others on key beats; each `<audio>` needs `data-duration`. Sources and fitting: "Sound effects and music" below.
8. `npx hyperframes lint` after each major section; `node <skill-dir>/scripts/lint_scene.mjs` after every patch and before every snapshot or draft render. A `//` comment goes at the true end of a line, never between two statements (it swallows the rest; exit 1 names `file:line`).

### Sound effects and music (Step 6, item 7)

SFX, in order: the bundled `/media-use` library (`node <skill-dir>/scripts/find_media.mjs --type sfx --bundled --query "<English words>" --out review/sfx`), then Openverse CC0 (`find_media.mjs --type sfx --query "<English words>" --licence cc0 --out review/sfx`, `--max-duration 3` for a short hit).

Music is a licensed free track, never generated, and every film has one: at Gate 2, `node <skill-dir>/scripts/music.mjs . <calm|bright|tense>` (by the energy; offline, so a down media site never leaves the film without a bed) copies a bundled public-domain / CC0 bed to `assets/music.mp3` with its `ASSETS.json` row; the assembler mounts it as `<audio id="music" src="assets/music.mp3" data-start="0" data-duration="{{END}}" data-volume="0.14" data-fade-in="1.2" data-fade-out="2">`. The user's own track, or a search they ask for (`find_media.mjs --type music --query "<1–2 English mood words>" --licence cc0 --out review/music`, CC BY only with a visible credit, never NC, ND or SA; then `find_media.mjs --take review/music/<file> --as assets/music.mp3`), replaces it.

`find_media.mjs` backs off on rate limits and reports a silent source as a WARN to rerun, never "nothing found"; the bundled bed stays meanwhile. Level: `audio_qc.mjs` (8–25 dB under the voice).

### Parallel build: pilot, then shot groups (Step 6, item 2)

Every film. The main agent never writes, patches or reads the film's scene code (`src/`, `assets/*.js` other than generated data; the Step 5 style frames in `style-frames/src/` it writes itself): it holds the gates, `BRIEF.md`, `storyboard.md`, `SPEC.md`, the beat map and the verdicts, and gives each job to a builder subagent that returns a short text. Log each delegation and report with `state.mjs log` (`"6 | pilot builder: <report> | -"`).

| Job | Who | Returns to the main agent |
|---|---|---|
| Pilot (item 3; under 3 groups the whole film), then the assembly (item 5) | one builder subagent (model and effort: `state.mjs next`) | files touched, lint/check result, draft path, open questions (≤ 15 lines) |
| Other shot groups (item 4) | one builder subagent per group | the same |
| Each QC fix round (`review.md` "How" item 3) | one builder subagent per round, given the P0/P1 list and the files | per finding: fixed / not fixed + one line; files touched |
| Fix check | a fresh subagent | pass/fail per item |

Every job gets a new builder, briefed with the files and the last report; never resume one (SendMessage). The reviewer is never a builder.

**Builder budget** (every agent that writes scene code, the style frames included). Put these lines in every builder brief:

- **Batch a round:** every edit of a round in one message (parallel `Edit` calls), then one snapshot.
- **Studio budget** (Express's: `express.md` "Token budget"): about 25 turns, 40 at most (a fix round: 12), ≤ 3 snapshot rounds per job, a report of ≤ 15 lines; then report what is open, a new builder takes the rest.
- **Stills as one sheet:** `node <skill-dir>/scripts/strips.mjs --frames <dir> --width 480`, read once.
- **Read a file once;** `grep -n` and `sed -n` for the lines needed.
- **Data before code:** a shot is a row of the shot list (`shots.js`); new code only in the set or a `custom` hook.
- **Parts before geometry:** the hero from, in order: the user's engineering data (CAD, STEP, KiCad); the code-first machine (`parts.js`, `assets/machine.js`; the default for object-studio); the library's Blender asset (`hero-asset.md`, curved or organic casings); a CC0 / CC BY model that passes the asset pair check; three.js primitives at real proportions last. An x-ray shell is `attend` with `edge` (`object-studio`).

`state.mjs approve` records the token report at every gate (`scripts/tokens.mjs`, `review/tokens.json`); a WARN row is a builder over budget: the rest of its job goes to a new one.

**Shot data first** (every 3D set): the builder writes the set (parts, measured `dims`, `stations`, `actions`, an `at(t)` posing parts from their cause) and one shot per storyboard row as data (`engine/three/shots.js`; format in `engine/three/README.md`, pattern in `engine/three/templates/object-studio-group.tpl.html`): `beat`, `action`, `transition` (`cut` | `travel`), camera keys (`station`, `at`, `arrive`), `cut`, `highlight`, `band`, `labels`, `dims`. `shots(SHOTS, { beats: BEATS, words: WORDS, end, fps, W, H, set })` plays it: `run.at(t, camera)` each frame, `run.draw(ctx, t, camera)` after the render, `layoutFrame` last. Every time is a cue (`"beat"`, `"beat.end"`, `"w12"`); the runner refuses a missing beat, an overshooting key, a label off the frame, a window under its read time and a shot whose subject does nothing. Code only for the set and a shot's `custom` hook (`{ at, draw }`). A fix round edits the data first.

1. **Group the storyboard rows.** Rows sharing one set or one continuous camera move are one group, one agent; otherwise split by scene. Name each group (`intro`, `stage-3`).
2. **Each group is a HyperFrames sub-composition.** Template `src/compositions/<group>.tpl.html`, `fill_times.mjs` into `compositions/<group>.html`. The host in `index.html`, the scene root and the `window.__timelines` key share the group id; every element id carries the group prefix; `data-start` and `data-duration` are local (`{{beat - first}}`, `BEATS.x.start - G0`, `G0 = BEATS.<first>.start`); `drawCaption` and `layoutFrame` take `t + G0`. Other format rules: `/hyperframes` `references/format.md`.
3. **Pilot.** A builder subagent builds the first group through items 3–6, renders a 10 fps draft with only its host mounted, and a separate subagent checks it against the style frames. Its files are the pattern for every group. Under 3 groups the pilot is the whole film: one builder, items 3–8, in `src/index.tpl.html` with no sub-compositions, then Step 7.
4. **Groups in parallel.** One subagent per other group, all in one message, strongest model. Each gets `SPEC.md`, its rows, the pilot's files (read-only) and the set modules; it follows items 3–6 and 8 with item 4 read for its group (its own template only, local times `{{beat - first}}`; it never edits `src/index.tpl.html`, the audio or another group's files), checks `npx hyperframes snapshot --composition <group>` against the style frames, and returns paths and a verdict, never code.
5. **Assemble.** A new builder given the pilot's report and the group paths: the hosts in `src/index.tpl.html` (`data-composition-src="compositions/<group>.html"`, `data-start="{{first}}"`), their order, the audio (item 7); then the blocking pass (item 5) on the whole film. A failed check goes back to that group's builder.
6. **Step 7 sees the groups.** `timing_lint.mjs` (no argument) follows each host into its group file and adds the host's start, so a cut inside a word or a clip under 1 s inside a group is reported with the group file and local time; an unreadable group file or one still holding `{{…}}` is exit 1. Run it on `index.html` only; `score_run.mjs` counts the same.

### Second-language cut: build (Step 6 again, same storyboard)

Only language-bound files change; no scene code, storyboard or SPEC edit.

- **On-screen words** come from `strings.js` (`window.STRINGS = { hook_kicker: "…", … }`, loaded with `<script src="strings.js">`, never imported) when `BRIEF.md` names a `second_language` from the start of Step 6; the cut adds `strings.<lang>.js` with the same keys. A build that typed its text first moves every string into `strings.js` (one Edit pass): `index.html` changes, so render the first-language draft, check it is unchanged and re-approve Gate 4 (`--by agent`).
- **Numbers** stay `numbers` from `model.mjs`, formatted with `Intl.NumberFormat(STRINGS.locale)`.
- **Captions:** `node <skill-dir>/scripts/captions.mjs narration.<lang>.txt audio/<lang>/words.json --out audio/<lang> --format <format>`.
- **Narration:** `loudness.mjs audio/<lang>/narration.wav --fix assets/narration.<lang>.m4a`.
- **Fill:** `node <skill-dir>/scripts/fill_times.mjs src/index.tpl.html index.html --lang <lang>`, and each `src/compositions/<group>.tpl.html` → `compositions/<group>.html --lang <lang>`. It takes times from `audio/<lang>/` and switches `audio/…` paths and any file with a `name.<lang>.ext` variant (a missing `narration.*` or `strings.*` variant is FAILED). A language-bound file it kept (an image with words) gets its `<lang>` variant, then a rerun.
- After the cut's final, run `fill_times.mjs` without `--lang`: `index.html` comes back byte for byte and Gate 4 reads approved again.
- Then `qc.md` "Second-language cut".
