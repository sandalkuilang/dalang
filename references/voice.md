# Voice engines: setup and use

Read the part you need: **Setup** when `preflight.mjs` reports a voice item as MISSING (`STOPPED` only needs `preflight.mjs --start`; `BUSY` needs only waiting), **Use** at Step 4. Free comes first: most users won't subscribe to a paid TTS.

| Engine | Cost | Timing source | When |
|---|---|---|---|
| **VoiceStudio** (local app, [github.com/debpalash/VoiceStudio](https://github.com/debpalash/VoiceStudio)) | free, on the user's machine | transcribes its own audio back with word timestamps | default |
| **ElevenLabs** (cloud API) — **paid** | free tier is tiny and non-commercial; paid otherwise | exact character alignment from the API | only when the user explicitly asks for it |

## Setup — VoiceStudio

- **Install** (ask first). macOS/Linux: `curl -fsSL https://raw.githubusercontent.com/debpalash/VoiceStudio/main/scripts/install.sh | sh`; Windows: `irm https://voicestudio.sh/install | iex`. It verifies the release checksum and installs the desktop app. Then start it: on macOS `node <skill-dir>/scripts/preflight.mjs --start` (it opens the app and waits ≤ 60 s); elsewhere open the app, then rerun preflight. First launch downloads a Python runtime (several GB, 10+ minutes): rerun preflight (`--start` on macOS) every few minutes until VoiceStudio reads OK, never your own polling loop. Leave the analytics consent prompt to the user. Intel Macs only get the UI; they need a remote backend (`--vs-url http://<host>:3900` on every preflight and `tts_timestamps.mjs` call). dalang sends no API key: a remote backend must accept this machine without one, or its reads come back "refused".
- **Models.** `GET http://localhost:3900/models`. Ready means `"installed": true` **and** `"incomplete": false` — `installed` alone flips true while weights are still downloading. For a missing model, tell the user its size and licence and get consent before `POST /models/install` with `{"repo_id": "…"}`; poll `GET /models/install/status`. A TTS model and a speech-to-text model are both needed (the second gives the word timing).
- **Recommended models:** TTS `k2-fsa/OmniVoice` (3.3 GB, 600+ languages, zero-shot cloning from a 3–10 s clip); ASR `deepdml/faster-whisper-large-v3-turbo-ct2` (1.6 GB, upstream MIT) on every platform, because the balanced tier activates it. (`mlx-community/whisper-large-v3-turbo` installs but the transcription endpoint won't select it; it wants the 3 GB `whisper-large-v3-mlx`.)
- **Activate the speech-to-text model.** Installing is not enough: transcription answers `asr_model_missing` until a tier selects it. After the faster-whisper model is installed: `PUT http://localhost:3900/api/settings/performance-profile` with `{"tier":"balanced"}` (same as "Install Balanced pack" in the app's wizard). Check `selections.asr` in the response.
- **Download big files outside the backend.** While the backend downloads something inline, it stops answering `/health`; after ~60 s the app kills and restarts it, the download starts over, and generation "loads forever". Fetch with VoiceStudio's own Python (macOS: `~/Library/Application Support/VoiceStudio/runtime/project/.venv/bin/python`, run from that `project` folder), in the background:
  - TTS watermark (58 MB, needed before the first generation): `python -c 'from audioseal import AudioSeal; AudioSeal.load_generator("audioseal_wm_16bits")'`
  - A model that keeps failing in the app: `python -c 'from huggingface_hub import snapshot_download; snapshot_download("<repo_id>")'`
- **Languages.** Quality follows training data: check the hours for the narration language in VoiceStudio's `docs/languages.md` (widely spoken languages have thousands of hours, many regional ones only a few) and warn the user when it is thin.
- **Licence.** The app is AGPL-3.0; model weights and generated-output terms are separate per model (VoiceStudio's Model Manager). The default TTS model **OmniVoice's weights are CC-BY-NC** (its Hugging Face card; only its code is Apache-2.0), so it suits learning and non-monetised videos. Tell the user before they plan to monetise. **The model that speaks is the one the user was told about:** `tts_timestamps.mjs` speaks with VoiceStudio's active TTS model (the one preflight reports) unless `--model` names another, prints `Model : <name> — <licence>`, and records it in `<name>.response.json` `_meta.model`. The narration's `ASSETS.json` licence is that model's output licence (OmniVoice `CC-BY-NC-4.0`, VoxCPM2 `Apache-2.0`, ElevenLabs free tier non-commercial), never the app's code licence; `check_assets.mjs` checks the row against the response file and fails a mismatch (table: `scripts/voice_licences.mjs`). A take whose voice the table cannot identify (a model not in it, an ElevenLabs plan that could not be read, a take made before the plan was recorded) is a `WARN` to check its model card or plan, never read as commercial-OK. A free, commercial-OK model that also speaks Indonesian and ~30 other languages is **VoxCPM2** (Apache-2.0, ~5 GB, MLX port in `mlx-audio`): VoiceStudio lists it (`openbmb/VoxCPM2` weights plus the `voxcpm>=2.0.3` Python package in VoiceStudio's venv — `uv pip install --python <venv>/bin/python voxcpm` added packages only, no upgrades; install with consent). Make it the active model in the app (or pass `--model voxcpm2`); `--instructions` is sent as its `description`. Measured on a 16 GB M5: Indonesian words transcribed back exactly, but ~22× slower than real time once loaded (5.8 s of speech in 127 s; the first call adds model load) and a request over 300 s of compute is abandoned, so the script sends it ~120-character chunks; a 60 s narration takes ~25 min. Run it alone (other model jobs starve it). Naturalness against OmniVoice is a human call: audition both.

## Setup — ElevenLabs (paid, optional)

- **No key?** Fine — use VoiceStudio. Never suggest ElevenLabs unprompted. Only if the user wants ElevenLabs, ask them to set `ELEVENLABS_API_KEY` themselves. Never show, print, or save the key to a project file. Never use a key pasted into the chat: ask the user to revoke it and store a new one in a real terminal tab (not the chat box — `read -s` gets no input there).
- `preflight.mjs` prints the tier and characters used. Tier `free`: about 10,000 characters a month (one 2–3 minute video plus auditions), **no cloning, no Voice Library voices and no Voice Design over the API** (402 / 403), non-commercial with attribution. On free, a regional accent is only reachable with an accent tag on a stock voice (e.g. `[strong Scottish accent]`) — or use VoiceStudio.

## Use (Step 4)

`<lang>` and the engine come from `BRIEF.md`. One script serves both engines and writes the same files; it defaults to VoiceStudio, add `--engine elevenlabs` for ElevenLabs. Commands and audition rules: `script-voice.md` §4.

- **Audition:** `--sample` speaks ~300 characters of whole sentences and prints words/s and chars/s. `--speed` ranges: ElevenLabs 0.7–1.2, VoiceStudio 0.25–4. Accent or style tags change the pace: calibrate with the exact tags you will use.
- **VoiceStudio voices:** `--list-voices` shows saved profiles plus `default` (OpenAI names like `alloy` are aliases for the default, not different voices). A fresh install has no voice for most languages, so **design** them: `--voice default --instructions "female, young adult, low pitch, calm"` (OmniVoice keeps its voice-design words: gender, age, pitch, accent, style). Same instructions + same `--seed` = same timbre: vary them between audition samples, never between sample and full take. In narration, `[tags]` are ElevenLabs-only and stripped; in a dialogue line a leading `[tag]` becomes that line's style.
- **ElevenLabs voices:** stock voices; library voices, design and cloning need a paid plan over the API. If it rejects `language_code` for the model, rerun without `--language`.

### Clone (VoiceStudio, free, local)

Only with clear permission from the voice's owner (the user's own voice, or a speaker who agreed). A clip from someone else's video or chat is not permission.

1. **Get 3–10 s of one speaker, no music.** Multi-speaker file → ask which speaker, find a clean window in its transcript (`--from-audio` on a copy, or VoiceStudio `POST /v1/audio/transcriptions`), cut it: `ffmpeg -ss <start> -t 8 -i <file> -vn -ac 1 ref.wav`. Music or noise under the speech → VoiceStudio `POST /clean-audio` (vocal isolation) first.
2. **Save the profile:** `node <skill-dir>/scripts/tts_timestamps.mjs --save-profile "<name>" --ref ref.wav --language <lang> [--ref-text "<exact words>"]` — it transcribes the clip when `--ref-text` is missing and prints the profile id. The same command freezes an approved designed sample as a profile (add its `--instructions` and `--seed`). A `--sample` audition is accepted as it is: a clip over 20 s with its `<name>.words.json` beside it is cut at the last word end ≤ 15 s (≥ 3 s), written as `<name>.ref.wav`, and those words become the ref text; any other clip over 20 s fails as before (and so does one with a `--ref-text`, which describes the whole clip).
3. **Use it:** `--voice <id>`, audition with `--sample` as usual. Record consent in the app (`POST /profiles/{id}/consent`) when the voice is not the user's own.
- **Dialogue (two or more characters):** write `narration.txt` as `name: text` lines with `(seconds)` pause lines. `--engine voicestudio --voices <name>=<voice>,<name>=<voice>` speaks each line in its character's voice (a leading `[tag]` becomes the style hint), inserts real silence for the pauses, joins everything, and transcribes it once. ElevenLabs has no multi-voice path here: use VoiceStudio or a recording.
- **The user's recording:** `--from-audio <file> --own-recording` (wav, mp3, m4a, or a video — the audio is extracted) keeps their voice track untouched and transcribes it for timing. Works for narration and dialogue. Untimed words (whispers, words drowned by music) are spread over their gap, and they never start inside a pause written in the script or a silence found in the audio. A warning lists any dialogue line that matched no word. `--own-recording` states the file is a human recording the user may use; without it the origin is unknown to the script and the take keeps the take it was cut from (`script-voice.md`).
- **Dialogue output:** `beats.json` gets `lines` and `beats.js` gets `window.LINES = [{ speaker, text, start, end }]`. Use it to cut to the speaker's close-up on `start`, to move mouths only between `start` and `end`, and to give the listener a reaction.
- **How VoiceStudio timing works:** it speaks the narration in ~700-character chunks of whole lines (120 characters for VoxCPM2, never over: a longer sentence splits at a comma, then at a space), joins them losslessly, transcribes them with word timestamps (the narration as Whisper's prompt keeps the spelling; spelled-out numbers may come back as digits — a "heard N words" warning, harmless when the beat words are timed) and matches the words to `narration.txt`; forced alignment then sharpens them.
- **Forced alignment (on by default when ready):** `scripts/align.py` times every word of the known script against the audio with a CTC model (Apache-2.0 models only; Meta MMS is non-commercial). Transcripts count a pause as part of the next word; the aligner puts sentence starts on the voice. Needs Python with torch, torchaudio, transformers, soundfile (VoiceStudio's venv has them; else `DALANG_PYTHON=<python>`) and a model for `--language`, downloaded once with permission: `<python> <skill-dir>/scripts/align.py --download --lang <code> --audio audio/narration.wav --text narration.txt --out /tmp/a.json` (id ~1.3 GB download, kept as ~0.6 GB in `~/.cache/dalang/align/`; en ~0.4 GB; ~3 GB RAM while running). Without a model the output says why and keeps transcript timing; `--align off` skips it. Tested end to end for `id`; ja/zh unsupported (no spaces between words).
- **Warnings to act on:** "low alignment score", "transcript heard N words", "words had no timing", or an unnamed beat. An agent cannot listen, so the script fixes them: `--retake auto` (add `--from-response audio/narration.response.json` for the take you already have) re-speaks only the flagged sentences alone (same voice and settings; the second try with another seed), splices each in at the pauses around it (10 ms crossfade, never inside a word), retimes the whole file and rewrites `words.json`, beats and `narration.response.json`. It names any sentence still flagged after two tries: respell it in `narration.txt`, then `--retake changed`. An unattended run never delivers a take with an open flag. Moving only `{}` markers? Recompute with `--from-response audio/narration.response.json`: no new generation, no charge.
- **Editing a few sentences:** `--retake changed` re-speaks only the sentences that differ from the text of the take on disk (a new one is added, a removed one is cut out) and splices them in; `--retake 3,5` re-speaks those sentence numbers. Both work on the take that exists, never a full take. VoiceStudio single-voice narration only: an ElevenLabs take, a sample, a recording and a dialogue are regenerated whole.
- **`503` from VoiceStudio:** a job ran over the compute limit and still holds the device, so a request sent at once would compete with it. The script waits (`DALANG_VS_BUSY_WAIT_S`, default 180 s) and retries once; still busy, it prints `WARN … rerun in a few minutes` and exits 3 (never `FAILED`). Rerun later. Never restart the app or switch engines for it: the device frees itself (BUSY means wait).
- **Neither engine available** (an Intel Mac without a remote backend and no ElevenLabs): use the voice path in `/media-use` (local Kokoro, free — check the language; HeyGen is paid, only if the user asks; autonomous mode stops instead), get word timing through `/media-use` transcription, match beat words by hand, and compare the transcript's word count with `narration.txt`.
