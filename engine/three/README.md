# DALANG three.js engine

Generic 3D systems proven on real renders: real scale and placement, true surfaces, simulated physics, cloth, air,
plants, particles, granular fills, water, fur, creatures that walk and climb, and the frame finish; plus a small catalogue of ready pieces built on them. Nothing
here knows a scene or a topic: every input is a parameter in real units, every preset (a kit's material names, a
palette, a particle kind) is passed in by the set. The rules behind every number
are in `references/looks.md` (true shapes and surfaces) and `references/camera-motion.md` §5 (physics, air, sound).

## Install into a video project

```bash
node <skill-dir>/engine/three/build.mjs <project>/assets
```

The build also writes `<project>/assets/.engine.json`: every file it copied, with its real origin and licence (the repo's MIT for the engine and examples; each vendored npm package, with version and licence, for the bundles). `scripts/check_assets.mjs` reads it, so these files are never listed in `ASSETS.json` by hand.

```bash
node <skill-dir>/engine/three/selfcheck.mjs <project>/assets
```

After each change to a set that bakes physics, and before any snapshot, preview or render:

```bash
node <skill-dir>/engine/three/bake.mjs <project>
```

It loads the composition once, headless, and stores every `bakeCached()` result in `assets/bake/<hash>.bin`; every
later page load (each snapshot, the preview, every render worker) replays it instead of simulating again. The hash
covers everything that decides the result, so a changed scene simply bakes again; `assets/bake/` can be deleted.

The build copies the modules and bundles `three-vendor.js` (three 0.186.1 and its add-ons, postprocessing, N8AO,
three-subdivide) and `rapier.js` (Rapier 0.14.0) from pinned versions; the first run installs them into
`vendor/node_modules`. The self-check fails loudly if a known trap is back (gravity not in scene units, a soft prop
that never comes to rest, a hull build abort, NaN in cloth or maps, zero normals, a tolerance that breaks at another scale or gravity, a cut cap coplanar with a face or a part the cut plane misses, a granular fill with grains on the removed side or stacked into one blob, a camera route that jumps (a hard cut), a ghost left on after its release, a dimension line or label outside the safe area). Import everything from
`assets/` so all modules share one `THREE`.

## What it covers, and how it grows

The engine holds behaviours (laws), never a list of objects. Rapier's rigid-body solver covers falling, rolling,
sliding, stacking, knocking and hinges for any shape: a phone, a bottle, a rock or a car is a model plus its
looked-up mass, friction and bounce (`dynamicHull(mesh, { mass, friction, restitution })`), no new code. The
systems: scale and placement, procedural surfaces, rigid physics with joints, hung cloth, swept organic forms with
fur, one shared air field (a breeze, jets from any outlet), plants that bend in it, particles in it, wind-driven
water, granular fills, section views, camera stations and attention, the finish. `examples/` holds ready pieces built on them, proof of how to use the systems, never required.

The engine is a toolbox, not the limit of what a film shows. Not here yet: sky and terrain, people (rigged
human characters), gallops, jumps and flight (creatures that walk and climb are here: `creature.js`), ropes, glass and liquids, flames, fracture, and every subject away from human-scale sets (molecules and ions,
cells and organs, orbits, fields, crowds, data in space; electricity and signals are here: `circuit.js`). A film that needs one builds it from three.js the same way:
the law that drives it and its real numbers from a cited source; parameters in real units, nothing that knows the
set; a scale changed on purpose and shown when reality is too small, large, fast or slow (`camera-motion.md` §5,
"Any subject moves by its own law"); its trap added to `selfcheck.mjs`; proved in the render; then brought back
here with a line in this table. Air is one shared field: every source adds into it and everything light reads it
(cloth, leaves, smoke, water ripples).

## Modules

| Module | What it gives |
|---|---|
| `kit.js` | `makeKit(scene, { mpu, floor, wear, palette, kinds, grain, gravity })`: sets the scale and the place (`M` metres per unit; `G` the place's gravity, 9.81 m/s² by default, in units/s²; live for every module; every tolerance is in metres, so any scale works); `model(path, opts)` loads a `.glb`/`.obj`, its materials dressed by name (`palette` colours, `kinds` surfaces: presets `kits.furniture`, `palettes.americanJapandi`; unmapped materials stay as they came), soft goods subdivided; `box`, `cyl`, `tube` (cables kept off the floor), `mat`, `cloth`, `canvasTex`, `group`, `paint`; `rest(o)` + `settle()` drop every prop onto its first contact by its own lowest points and return what could not be placed (nothing below, or more than 3 cm inside something; up to 3 cm it lifts out); `model(path, { crease: false })` keeps a detailed model's own normals; `model(path, { palette, kinds, real })` gives a found (CC0) model its own look, merged over the kit's and never leaking into it, and its stated size `real = { h, w, d }` in metres, which `scaleAudit` checks (none: listed unchecked); Draco-compressed glTF loads (the wasm decoder is copied to `draco/` and listed in `.engine.json`); `screenOn(model, material, picture)` lays a display on the model's own screen face. |
| `surfaces.js` | `surface(material, kind, { world, wear, floor })`: procedural triplanar detail with no UVs — `fabric`, `pile`, `wood`, `bamboo`, `plaster` (wear 0..1), `micro`, `bark`, `stone`, `soil`, `grains` (packed grains, `{ size, long }`). |
| `physics.js` | `makeSim(THREE)`: Rapier in real units. `staticScene(scene, exclude)`, `roundBox`, `dynamicHull` (spokes, joints, soft), `kinematicHull`, `hold(body, t)` (out of the solver until its cue), `bake(duration, onStep, preroll, { track })` → `{ impacts, report, apply(t), travel(t, fps), pose, at(name, t) }`, `bakeCached(...)` (the same, stored in `assets/bake/` by `bake.mjs` and replayed; one per sim, after `audit`; `{ keep }` carries what onStep built, `{ key }` any value an inline script feeds the bake, `{ islands: [[a, b], [c]] }` bakes groups that never touch in parallel workers), `audit(objects)`. `slow(t0, rate, rampOut, hold)` and `replay(tEvent, tShot)` return `tau(t)`, a time remap for slow motion and replays of one baked event: `apply(tau(t))`, `pose(i, tau(t))`, `travel(t, fps, tau)`. | `bakecore.js`, `pool.js`, `bake-worker.js` | The bake's step loop without three.js or the DOM, the pool that runs declared islands in workers (one per spare core, in this thread when none starts), and the worker itself. Used by `physics.js`; a set never imports them. |
| `bodies.js` | `loose(sim, objects, { kg, friction })`: soft things that are not placed (cushions, bags, a dropped coat) settle by simulation in the pre-roll. |
| `mechanism.js` | `slide(sim, part, { axis, min, max })` and `hinge(sim, part, { at, axis, min, max })`: a part (what `roundBox` or `dynamicHull` returned) on a prismatic or revolute joint whose limits are its stops (m, or rad; the start is 0, inside them); `spring(sim, joint, { stiffness, rest \| preload, damping })` (N/m and N, or N·m/rad and N·m; refused when too stiff for the 480 Hz step); `latch(sim, part, until)` holds the part in place, still colliding, until a time in s or a condition `(t) => boolean`, then lets it go once. Baked with the set: hashed into the cache key, release times in `report.latches`, refused in `opts.islands`. The frame is the set; a part on a moving frame is not covered. `hinge` with `min: -Infinity, max: Infinity` is a free axle (a wheel, a gear, a pulley); `spring` refuses a free axle and stops past ±π (it reads the angle within a half turn, and would flip its torque past it). **Couplings** tie one part to another at the real ratio in the same bake (never a second rotation animated from the first): `gear(sim, a, b, { teeth: [za, zb] \| ratio, internal })` (whole tooth counts ≥ 6; b turns at za/zb the speed the other way, an internal gear the same way), `belt(sim, pulleys, { slip, pitch })` (`[{ joint, r \| teeth, inside }]`: every pulley follows the first at the radius ratio × (1 − slip); an idler on the back turns the other way), `chain(sim, sprockets, { pitch, shifts })` (`[{ joint, teeth }]`, pitch in metres per link; `shifts: [{ at, index, teeth }]` moves the chain to another cog of that wheel at a time: the ratio changes at once, the angle does not jump), `cam(sim, camJoint, followerSlide, profile)` (the follower's lift in metres from `profile(θ)`, 0 at the start, one turn periodic, inside its stops; it stays on the profile). Two-way: a driven inertia comes back to the driver as s²·I, the report's `ratio(i)`, `angle()` and `torque(i)` (`{ driver, driven }` in N·m, N for a cam's follower) give what the bake ended on, stored with it (`report.couplings`): after `bake` or `bakeCached` the same numbers on a live bake and on a cache hit, before it the first ratio, angle 0 and no torque; a cam profile is hashed by its values as well as its source; and a latched or kinematic wheel holds the whole train. Axles are parallel and the wheels of a pair share a collision group (`dynamicHull(…, { group: 1 })`) or `gear` refuses. Not covered: bevel and worm gears, a rack and pinion, linkages. |
| `transmission.js` | The geometry of what the couplings tie together, in metres (scale a mesh by 1/M). `involute({ module, teeth, pressure, backlash })`: a spur gear outline at a real module (2 mm, not 2) and tooth count, with `rp rb ra rf`; `meshing(g1, g2)` gives the centre distance m(z1+z2)/2 and the phase at which two mesh, and refuses an interfering pair (12 teeth at 20° against 36: use 25°) or a contact ratio under 1; `gearGeometry(g, { width, bore })` the extruded solid. `pitchRadius(teeth, pitch)`; `loopPath(wheels)`: the closed belt or chain path over `[{ x, y, r, inside }]` (counter-clockwise, `at(s)` gives the point and travel direction); `openLength`, `centreFor({ links, pitch, r1, r2 })` (the centre for a whole number of links); `linkPoses(path, { pitch, phase })`; `angleOf` and `phaseOf(q, q0, axis, teeth, pitch)`: where the links are, from the driver wheel's replayed pose alone (any frame order, render workers included). |

| `type.js` | Captions and labels on the film's 2D canvas, no imports (browser and Node). `readTime(text)`: the least time a label needs on screen (0.5 s + 0.3 s per word + 0.15 s per CJK character, at least 1 s). `phrases(narrationTxt, words)` → caption phrases (`craft-rules.md` §6: a narration line end, sentence ends, `,` `:` after 3 words, a run over 7 words at its longest speech pause in `words.json` (≥ 0.3 s) else balanced, CJK by character ≤ 16, held through the pause that follows; `scripts/captions.mjs` writes `audio/captions.js`); `drawCaption(ctx, t, caps, { format, accent, pill })` in the format's caption zone (the target band of `craft-rules.md` §6; Reels and TikTok: block top about 73 %, bottom 82 %), ink from the luminance under its own box (decided every frame, halo in the other ink), the spoken word boxed in `accent` from its start, never drawn outside the zone (a phrase that does not fit in two lines at 54 px shrinks: `shrunk`); | `circuit.js` | Electricity made visible, every `at(t)` a pure function of t from the numbers model's functions (amperes, volts, watts, joules), never keyframed. `wire(path, { kind, radius, color, normal })`: a `trace`, `wire` or `busbar` along ≥ 2 points (straight legs with round corners) or a `THREE.Curve`, typical radii 0.4 / 1.5 / 4 mm (override from the part); `length` in m, `pointAt(s)`, `frameAt(s)` (s in metres from the start). `flow(wire, { current, waveform, freq, speed, timeScale, fps, amplitude, duty, full, width, perAmp, color, samples, lift })`: pulses travelling at the stated visualisation `speed` (m/s, not drift velocity) in the waveform's shape: `ac` a sine wiggle (wavelength = speed / shown frequency), `dc` a straight line, `pwm` chopped blocks (`duty`), `3phase` three ribbons 120° apart; width = `width + perAmp × |I|`, brightness = `|I| / full` (the film's one scale: two flows share it), no current draws nothing. Mains frequency cannot be seen at 30 fps: `timeScale` slows it on purpose (shown = freq × timeScale) and a shown frequency above `fps / 4` is refused (`/alias/`), as is a wavelength under 6 samples; `label` is the on-screen line ("AC 50 Hz shown at 1/10 speed; a type with no curve is refused; the light stays in the scene at intensity 0. `arc(kit, { from, to, t0, dur, energy, efficacy, timeScale, fps, seed, branches, sparks, sparkSpeed, sparkTemp, cool, ground })`: a seeded branching discharge; sparks fly by gravity from the middle (closed form, no drag) and show by black-body colour until they cool below 798 K; `events` is the `sfx.js` row (`arc-flash`). `at(t)` → `{ on, intensity, sparksLit }`. `failure(part, { kind, at, amount, vent, soot })`: a Mesh that fails at the model's event time `at` (s): the variant (`bulge` a domed, optionally vented capacitor top; `blown` a fuse wire in two pieces with a gap and a soot mark; `char` a burnt resistor or varistor; `melt` a sagging connector) is built once beside the part with its own geometry and material, `at(t)` shows the part before the event and the variant from it (pure of t, the part's own material never written); an unknown kind or a non-finite `at` is refused. Nothing here adds itself to the scene; `scaleAudit` lists these `unchecked`. |

## The shape of a set's build

1. `makeKit` with the measured `mpu` and the floor's height; place models and props, `rest()` what is set down.
2. `settle()` once everything is placed; read what it could not place. Declare the real size of each hero prop (`userData.real = { h: 0.18 }`) and read `scaleAudit(scene)`: a 10x typo is named here, not by a reviewer; `zFight(scene, { cameras })` with every station's camera before the bake.
3. Air (`block` with every obstacle in place), cloth bakes.
4. `makeSim`, `staticScene` (excluding what moves), dynamic bodies and rigs, mechanism parts and the transmissions that tie them (`mechanism.js`, `transmission.js`), `hold` for what enters on a cue,
   `audit`, then one `await bakeCached(...)` for the whole set with a pre-roll (≥ 1.2 s with loose props): a replay
   does not run onStep, so a per-step value it computes goes in `track`, anything else it builds in `keep`, and a
   value from an inline script in `key` (the set's `assets/` modules and `beats.js` are hashed already). Read
   `report` and the bodies' stillness at frame 0. Then `bake.mjs` once, before snapshots and renders.
   A bake is one world on one core, every step after the last. When groups of bodies never touch for the whole shot
   (a counter and a far shelf, two workbenches, the two pavements of a street), declare them:
   `bakeCached(duration, onStep, preroll, { islands: [[mug, bowl], [lamp]] })`. Each island is its own world, baked
   in a worker while this thread bakes the main island (every body not listed): the same `{ pose, impacts, report }`,
   the same cache file. Only the main island runs `onStep`, the kinematic paths, `track` and `keep`: a script that
   reaches a declared body throws (its methods, a lookup of its handle, and every world-wide query: `castRay`,
   `intersectionsWithShape`, `contactPairsWith`, `forEachCollider`… cannot tell a body baked in another world from an
   empty place, so they refuse; read a main-island body through its own methods), a kinematic body, one impact name on bodies of two islands or a joint across
   islands is refused, and a body of one island coming within 5 mm of another's (judged on what can touch: every
   collider of the body, with its offset and contact skin, and the drawn geometry, so a collider built wider than its
   mesh counts; on the path between two steps too (a fast body refuses the bake, see below; a slow one is judged as a capsule widened by how far the step's speed and spin let it stray), and from where a script put a body, never along its teleport; in the pre-roll as well as the shot: a piece that settles onto a declared body there would fall through
   it in its own world) throws with the pair and the time, so merge those islands. While the islands bake, a script may
   change a main-island collider's friction, restitution, mass or filters, never where it can touch (shape, size, offset,
   contact skin: those calls throw, and a collider that reaches further after the bake is caught). What every island world shares with the main one
   is fixed when the bake starts and the scripts may not change it: gravity, the solver settings, every fixed body
   and static collider (move, disable, remove, add), joints inside an island, a step of the world. Those calls throw
   while `onStep`, `track` or `keep` run (reading them stays open, as does driving a main-island body), and a change
   that slips past is caught after the bake: nothing is saved. A dynamic body the sim did not make is refused too.
   Set such a change up before the bake, or leave the bodies it touches out of `islands`. A worker that cannot start falls back
   to this thread (a warning, same result, no gain). Gain: the slowest island's time, not the sum. Islands are for sets
   that settle slowly (stacks, props, pieces dropped or nudged): a body moving over 10 mm in one step (about 4.8 m/s at
   480 Hz, spin included: a free fall of about 1.2 m, a throw, a piece dropped from above the frame) refuses the island bake, since inside a step Rapier's CCD can stop a fast body and pass a hit
   on in ways no recorded pose shows. Bake such a set as one world.
5. Render loop: pose everything at `t` (a slowed or replayed shot at `tau(t)`); when `travel(t, fps)` passes ~4 px of a frame, average 5 sub-frames across a
   180° shutter through `finish.layer`, then `finish.grade(t)`.
6. Sounds on `impacts`: `impactSounds(bake.impacts, { library, assets, materials, against, latches, events })` (`sfx.js`; or `node engine/three/sfx.mjs <project> --bake <file> --plan sfx.json`) returns the `<audio>` rows and the table to approve; rolling and sliding sounds follow the measured speeds (`camera-motion.md` §5.3).

### A mechanism on cue, and its slow-motion replay

A spring-loaded plunger held by a latch, released on its cue, then shown again 50 times slower from another camera. One
bake; both shots read it.

```js
import { slide, spring, latch } from "./mechanism.js";
import { slow, replay } from "./physics.js";
const part = sim.roundBox(plunger, 0.02, 0.02, 0.06, 0.002, { density: 7850 * M ** 3, name: "plunger" });
const j = slide(sim, part, { axis: { x: 0, y: 0, z: 1 }, min: 0, max: 0.03 }); // 3 cm of travel to its stop
spring(sim, j, { stiffness: 400, preload: 6 });            // N/m, and N at the held pose
latch(sim, part, beats.release);                           // or (t) => trigger.body.translation().y < y0
const baked = await sim.bakeCached(4, onStep, 0.5, opts);
const tRel = baked.report.latches[0].t;                    // when it let go, also from a cached replay
// shot 1 in real time; shot 2 (from shot2 s) replays the release, 1/50 slower for a moment, from another angle:
const again = replay(tRel - 0.05, shot2), ramp = slow(shot2 + 0.05, 1 / 50, 0.6);
const tau = (t) => (t < shot2 ? t : again(ramp(t)));
baked.apply(tau(t));
```

The released part never shows back in its held pose: every shot reads the same baked motion. A part that must go back
needs a visible cause (a drive, a press), built as a body or a joint, not a second time function.

### A transmission

A 12-tooth pinion driving a 36-tooth gear, and a chain whose links move with the cranks. The ratio is in the bake, the
shapes are real size; nothing turns the second wheel by hand.

```js
import { hinge, gear, chain } from "./mechanism.js";
import { involute, meshing, gearGeometry, loopPath, linkPoses, phaseOf } from "./transmission.js";
const free = { min: -Infinity, max: Infinity }, Z = { x: 0, y: 0, z: 1 };
const a = sim.dynamicHull(pinion, { group: 1, mass: 0.05 }), b = sim.dynamicHull(wheel, { group: 1, mass: 0.4 }); // one collision group
const ja = hinge(sim, a, { at: pa, axis: Z, ...free }), jb = hinge(sim, b, { at: pb, axis: Z, ...free });
gear(sim, ja, jb, { teeth: [12, 36] });                  // b turns at 1/3 the speed, the other way; the drive is a torque on a
const g1 = involute({ module: 0.002, teeth: 12, pressure: 25 }), g2 = involute({ module: 0.002, teeth: 36, pressure: 25 });
const { centre, phase2 } = meshing(g1, g2);              // centre 48 mm; refuses a pair that interferes
pinion.geometry = gearGeometry(g1, { width: 0.01 });     // metres: scale the mesh by 1/M
// a chain: links on the loop, at the phase the driver's replayed pose gives
const path = loopPath([{ x: 0, y: 0, r: R1 }, { x: C, y: 0, r: R2 }]);       // C from centreFor({ links, pitch, r1: R1, r2: R2 })
const poses = linkPoses(path, { pitch, phase: phaseOf(pinion.quaternion, q0, Z, 42, pitch) }); // after baked.apply(t)
```

A latched wheel holds the whole train; the driver feels the load as the driven inertia times the ratio squared. See
`examples/drivetrain.js` for the whole thing with a gear shift.

### A creature walking

A small lizard crossing a floor and climbing a wall: the gait, the stride and the footholds come from its size and
speed and from the set's own surfaces, nothing is keyed.

```js
import { makeLizard, wallClimb } from "./examples/lizard.js";
floor.name = "floor"; wall.name = "wall";                 // what a foot touches is reported by the mesh's name
const liz = makeLizard({ length: 0.12 });                 // metres; breath: { rate } only with a cited rate
k.scene.add(liz.creature.group);
const walk = wallClimb(k, liz, { wall: { x: 0.4 / M }, from: new THREE.Vector3(0, y0, 0), height: 0.3 / M, speed: 0.05 });
walk.look(lamp.position, 2.0);                            // the head turns toward a point from t = 2 s (before the first apply)
walk.steps.forEach((s) => sfx.push({ t: s.t, name: "foot", at: s.at }));  // a touchdown per step: leg, object, point (metres)
const when = walk.together("wire A", "wire B");           // the first t of the walk one foot is on each, null if never
// per frame:
walk.apply(t);                                            // body, trunk sway, legs, breath, head
```

Any other animal builds its sweeps and calls `rig(body, { legs, cling, head })` and `path(creature, curve, { scene, speed,
gait })` directly (`tripod` for a six-legged insect, `walk` or `trot` for a quadruped). To let it push props, give the
physics a `kinematicHull(root, (t) => pose)` fed from `walk.at(t).body` (`p` in metres: divide by `M`; `q` as a
quaternion). The body is one rigid frame that sways, so a corner's radius is chosen against the body's length.
